# ClawSense 当前阶段收尾计划

这份文档用于给当前短期目标一个明确的结束方式，避免项目继续在局部优化中无限打转。

## 1. 当前阶段的真正目标

当前阶段不是要把 ClawSense 做成最终版“全天记忆大脑”，也不是只做音频 + 图片总结器，而是要先稳定证明下面这件事：

- 用户可以通过旧手机直接用语音接通 OpenClaw
- ClawSense 能把现实世界 evidence 检索给主模型
- OpenClaw 能基于真实 evidence 与用户继续沟通、追问、解释、建议和沉淀
- 手机能把回答读出来，并展示完整答案

这里的“有用回答”必须明显建立在：

- transcript
- 图片 / 场景证据
- speaker / 人物标注
- 待确认缺口
- OpenClaw 主模型的自然语言理解与推理

而不是主要靠弱 summary 或过度推断。

## 2. 本阶段的冻结线

从现在开始，本阶段不再继续横向扩需求。

### 2.1 不再继续扩的内容

- 聚会 / 社交的主动洞察能力
- 真正的 speaker diarization
- 整天所有音频的完整高覆盖 transcript
- 所有 provider 的完美统一路由
- 更强的主动发现层

这些内容保留到下一阶段。

### 2.2 当前只做收尾的内容

本阶段只继续做下面 4 类事情：

1. 语音对话入口真实问答质量收口
2. 时间范围和 evidence 路由收口
3. TTS 播报 / 屏幕完整答案 / 追问体验收口
4. 稳定性和可发布性收口

## 3. 当前阶段完成标准

只要下面 4 组标准同时满足，就判定当前短期目标代码迭代完成。

### 3.1 语音对话入口可用

用户提问：

- 过去4小时我们聊了什么？
- 昨天发生了什么？
- 刚才看到了什么？
- 刚才讨论的重点是什么？
- 你怎么看这件事？

回答中应稳定出现：

- 正确时间范围
- 音频转写和画面证据
- 主模型自然回答，而不是纯模板
- 屏幕完整答案
- 可听懂的 TTS 摘要

并且不应再大量出现：

- 环境音被当成用户问题
- 问昨天却只看最近图片
- 明明有音频却只回答图片
- TTS 只读前两句导致用户误以为回答丢失

### 3.2 连续追问初步可用

用户提问：

- 详细说说第二点。
- 简短点。
- 读全文。
- 帮我整理成会议纪要。

回答中应稳定出现：

- 对上一轮问题 / 时间范围的继承
- 明确的可执行意图
- 如果已经创建草稿，必须返回文件路径；如果创建失败，必须明确说明失败原因，不能假装完成

### 3.3 音频补强链成立

对一个典型办公日或课堂日：

- 至少关键音频窗口能通过 ingest / query-time recheck / background backfill 补出可用 transcript
- 不再长期停留在“只有音频，但完全没有任何内容可引用”
- 聊天页回答开始真正引用 transcript，而不是只引用图像和弱 summary

### 3.4 标注和稳定性成立

需要成立：

- `speaker_1 / speaker_2` 能暴露并可回填
- 人物 / speaker 标注写回后，后续回答能复用
- 401 心跳 / 503 队列满 / 长时间上传失败不再频繁打断正常使用

## 4. 当前阶段建议的最后一轮开发范围

当前阶段建议只再做这些收尾项，不再继续加新能力：

1. 再收一轮语音对话输出
- 重点是：
  - 过去4小时
  - 昨天
  - 刚才看到 / 听到
  - 你怎么看 / 帮我沉淀

2. 再收一轮模型回答链路
- 让大模型基于 evidence 回答
- 模板只做 fallback

3. 再收一轮播报策略
- 摘要播报
- 屏幕完整答案
- 后续补 `读全文 / 停止朗读`

4. 不再继续扩功能面
- 除非发现真实阻塞短期目标达成的问题

## 5. 当前阶段的最终交付物

本阶段结束时，应该留下这几类交付物：

### 5.1 代码侧

- 稳定的 evidence-first `clawsense_context`
- query-time audio recheck
- background audio backfill
- `assistant/query` 的 evidence + model + fallback 链路
- TTS 摘要与屏幕完整答案双通道

### 5.2 文档侧

- 当前目标与阶段记忆
- 当前阶段收尾计划
- README / 部署文档的当前真实能力说明

### 5.3 验收侧

至少留下一组真实问答样例：

- 办公场景
- 上学 / 课堂场景

用于说明：

- 任务
- 人物
- 学习要点
- 待确认缺口

已经达到“可传播、可演示、可继续迭代”的水平。

推荐同步保留一份机器可判定验收报告：

- `openclaw clawsense acceptance 7`

该命令会按最近 N 天（默认 7 天）输出 4 项收尾标准的 `pass / needs-work / missing-data` 结果，用于明确当前离“短期目标完成”还差什么。

## 6. 下一阶段再做什么

当前阶段一旦完成，下一阶段才正式进入：

1. TTS 停止控制的真机闭环验收
2. 草稿文件在聊天页 / Web UI 的可见性
3. 更高覆盖率的整天 transcript
4. 真正的 speaker diarization
5. 视频 M1 与关键帧结构化
6. 全天记忆向量化增强

## 7. 一句话收口判断

当前阶段的正确收尾方式不是“继续加更多能力”，而是：

- **把旧手机语音入口做到稳定可用**
- **把 evidence 路由、大模型回答、TTS 播报收口**
- **把视频、diarization、全天记忆增强留给下一阶段**
