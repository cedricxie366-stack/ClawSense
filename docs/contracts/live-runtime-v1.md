2026-10-21更新：Host0.2.0-preview.8／Android0.3.8采用以下准备与实时输入约定。此处描述行为，不代替日期验收结果。

- `POST /api/clawsense/live-prepare`复用设备认证和处理位置／项目权限，仅准备本机模型资产，不启动麦克风、相机或会话；最多四个并发准备请求。手机进入Live页提前准备语音，选择镜头时可准备视觉资产。缺少新接口的旧Host保留原开启路径。
- MLX角色禁用未使用的Torch／TF后端；语言与TTS按需加载权重，但必须完成真实预热才能返回就绪。各角色的加载／预热可交叠；`initializationMs`表示连接的完整初始化，旧`modelWarmupMs`在本版本表示加载后剩余的准备阶段，不能跨版本直接当作总启动时间。
- 镜头已选择时，在就绪前完成视觉资产准备；它不使用真实照片、不执行视觉分析。最后连接离开后的60秒空闲会冷却模型，并释放仅因准备操作留下的视觉进程；真正结束采集仍立即释放手机硬件。
- Live单独会话按20ms送出16kHz PCM，连接启用TCP_NODELAY避免传输层再合并小包；原环境录音分帧保持。Silero窗口不足32ms时沿用上一判断，不把“尚无新判断”误作静音。短停止口令可作最多六次有限前缀核对，只接受明确口令，不把相近词自动改成“停”。
- 每片声音仍检查当前凭据和政策文件身份；小型文件元数据检查不排队等待资料落盘，变更后的正文异步合并重读，检查期间再次变更仍重新核对。认证前的声音也保序并受两秒／64KB及200包上限约束；停止可越过待查队列，旧输入不能在停止后重新进入。播放状态按最后收到的有效状态生效，迟到的旧状态不能覆盖新状态。
- 手机先按EXIF处理旋转和镜像，再缩放并生成无旋转标记的JPEG；后端也处理其他客户端保留的EXIF，避免模型看到的方向与照片预览不同。当前画面问答检测过暗或缺少细节的输入，明确说明看不清；概览只回答主要物体，细节问题另按所问内容处理。概览在完整首个分句后结束生成，不将额外猜测写成观察。识别仍是待核对的模型观察，不提高本人确认权威，也不保证任意物体都能识别正确。

2026-10-20声音稳定性：本地TTS使用由选定voice／style派生的固定采样seed，不由输入正文、前一次请求或取消推进同一音色的随机状态。正常逗号分句尽量合并，180ms无后续生成时可释放已有分句，长文本仍有有界流式输出。固定采样提供可复现性，不保证跨文本的感知音色一致或自然度；必须保留相应真人听验。

## 处理位置与开始／结束

Android 仍由同一个 AudioRecord 服务已明确开启的记录及 Live。单独 Live 不保存环境原始录音，不自动恢复采集；镜头需在开启前另行勾选，只按视觉问题拍新照片。感知模式保留原音频、图片及手动短视频入口。结束全部服务释放录音、相机和播放器；初始化／音频占用失败也结束 Live-only 服务。

2026-10-20起，Android显式点击开启Live会在hello发送可选的`invited: true`。点名回应模式的开场30秒允许普通语音直接进入，随后恢复点名及连续追问窗口；普通连接、环境输入、安静模式和宿主任务的点名限制保持。它不提供身份确认或新的私密读取权限。界面聆听状态同时要求连接就绪和输入帧已送出。

Live播报使用媒体语音属性及`ALLOW_CAPTURE_BY_NONE`，按系统当前媒体输出，不强制扬声器或改系统音量。页面音量键控制媒体。非阻塞PCM写入与取消、清缓冲、释放按代次同步，停止后的旧包及旧完成回调不得影响新轮次。修复和限定真机结果见[10月20日续验](../validation/p1-human-2026-10-20.md)。

默认基础能力在自有电脑：Paraformer 流式识别、SenseVoice 中文整句复核、直接 Silero VAD、Qwen3-4B-Instruct-2507 文本、Qwen3.5-2B 视觉、Qwen3-TTS 1.7B 音色与语调。已有配置须显式升级模型目录，不能仅凭代码版本推断实际模型。`asrFinalLanguage` 可选 zh/en/auto，中文预览默认 zh。模型文件已准备后，基础运行不自动下载资产或回退外部模型。手机 ML Kit 中文 OCR、本机裁剪和遮挡另有独立入口。这不表示纯手机全链推理。原生语音适配仍按实际探测，当前 Mac 串联方案 `fullDuplex=false`。

DSH、Codex 只在配置且来源／接收方授权允许时执行工作；失败不静默外发。公开场景当前不执行拥有私有工具的宿主工作。DSH 工作目录隔离不等于完整操作系统沙箱；外部副本不在 ClawSense 擦除保证内。

## 连接、媒体与来源

GET/PUT `/api/clawsense/live` 读取／保存设置；WebSocket `/live` 用原设备 Bearer 认证，禁止 URL 凭据。`hello` 后检查模型进程并按实际声音预热，再返回实际能力与 `ready`，一设备一个会话。Host0.2.0-preview.7曾将视觉加载移到提问时；preview.8改为在选择镜头后提前准备资产，拍照和分析仍只发生在实际提问时。声音准备按音色与进程代次复用。最后连接断开后保留60秒声音准备状态，重连仍重新检查模型就绪，不能沿用已退出进程的结果；期间没有采集。准备时间`modelWarmupMs`与首次加载、网络及每轮回答等待分开记录。

16kHz 单声道 PCM16 走二进制；控制事件有 text、interrupt、playback、audio_ack、persona、frame、task_cancel、task_resume、close。每条输入检查原子凭据／政策文件身份，变化后重新读元数据；音频热路径不进入证据写锁。来源读取、模型输出、成果写入仍遵循共同协调器和快照。严格本地或项目不允许时，不接收这条协同通道的声音／画面。

视觉问题发出一次性 `vision_request`。照片须匹配请求 ID，拍摄／传输在两秒窗口内，超时不使用旧图，也不把上轮视觉答复继续显示成本轮结果。客户端JPEG最多200KB，对应WebSocket控制帧容量320KiB；格式和请求校验独立执行。问题涉及变化时可取得连续两帧，只比较状态差异，不能据此声称理解了全部中间动作。原始 JPEG 只在该轮处理；保存的是带时间、哈希和权限的模型观察。它不是本人确认的事实，也不能猜人物身份。历史观察与当前镜头分开处理。

输出携带会话、轮次、序号和时间。客户端不播放已打断的旧轮次；识别、传输、合成及播放队列都有容量和时限。起音预录、中文短口令复核、系统 AEC 和文本回声检查互补，不能代表任意电视／多人场景零误触发。

Host0.2.0-preview.6增加兼容事件：`input_status`含单调输入编号和处理结果；`recognition_comparison`含相同输入的选用结果及最多400字符备选；`input_health`约每秒一次，仅包含帧数、音量峰值、语段／队列与结果计数。所有事件沿用设备认证及会话序号。来源失效或新输入后不发送迟到备选，客户端同时丢弃旧编号。备选不写入历史或确认事实，不作为模型输入，不等待慢识别器完成才回答。“accepted”只表示已接收这句话，不是记忆确认。手机修改识别后发送的是新问题，原记录保留。preview.6离线报告当时尚未验证实体机；后续OPPO失败与preview.7修复见[本轮记录](../validation/p1-oppo-recovery-2026-10-20.md)。

实时分帧处理、中间转写、整句复核／历史写入分开。中间转写落后时只保留两秒待转写片段；完整语段仍保留，最多约20秒，供整句核对或全段重识别，不依赖不完整中间文本作答。派生转写是否降级写入计时，不能把它说成原始声音已经丢失。整句工作保序，最多两条待处理；停止、更新的直接输入或权限变化使旧结果失效。采集本身按两秒／64KB和200包双限，超限明确停止。回声匹配容许中文单个数字与阿拉伯数字的表示差异，但相似长句里发生金额／星期变化时保留为新内容；这不是说话人身份验证。

preview.7增加`fragment_ignored`及`interruption_unclear`回执：未成句代词片段不另起回答，附和不触发新一轮。播报期间的未知单字最多等待另一识别器250ms，不能确认时暂停并显示`unclear_interruption_paused`，不自行恢复、不解释该字的新话题，也不把它改写成停止口令。这是普通输入不等待慢识别器的一个有界例外。

## 会话、记忆与确认

开启先点名，随后30秒可连续追问；长时间安静后重新点名。语音发起宿主工作需点名，环境材料不成为执行命令。声音停止与任务取消是两种控制：前者停止生成／播报，后者必须取得执行端停止结果。取消不撤回已经产生的外部动作。

当前安排优先采用获准的本人确认；询问“录音里当时说什么”只引用录音识别文本，不能把后来的确认、助手旧回答说成原话。更正不抹去旧识别，也不提高识别文本本身的可信度。

最多200条近期消息可按时间／关键词查看。来源更新的历史可标注过期供本人回看，不能继续作为当前答案；删除或撤销后的文本不交付。来源／权限变更主动复核当前回答并停止旧播放。会话、执行请求和成果副本纳入共同删除管理；迟到保存不得恢复被删除正文。原有显式问答入口也拒绝 stale/unavailable 缓存。

主手机 GET/POST 的数字接口使用独立配对与项目授权。`digital/confirm` 要求会话版本及每个来源 `{kind,id,revision}`；旧缓存不能确认后来变化的原文。可信手机交互可接受／拒绝／取代成果、确认／撤回人物关系；模型填写“已确认”没有这项权威。只有当前且本人接受的成果用于下次复用。

## 持久工作与回流

工作与收音／播报独立。请求 ID 持久化；同设备同 ID 的重连重放不再执行，内容或目标宿主变化但复用 ID 被拒绝。状态有 queued、running、waiting_user、completed、failed、cancelling、cancelled、interrupted、execution_unconfirmed；当前适配没有通用的跨宿主人工审批续接，遇到这类限制需保留真实状态。

DSH SDK 及 Codex CLI 使用独立会话／工作目录。显式取消终止受控执行端，未确认不能标为取消。重启时中断的未派发请求可显式恢复；已派发请求必须核对，不自动重跑。关闭服务不能在关闭后新派发请求。

文件请求必须取得可核实的受控工作目录文件；不跟随符号链接，限制格式／容量／修改时间并验证 UTF-8。只声明文件名而没有文件不能完成任务。手机读取 GET `/api/clawsense/live-result` 查看正文／文件和本人复核状态。已保存、已接受、已发送、已送达各有独立含义；此预览不以草稿生成声称发送。

## 离线与测量

主手机共同背景缓存最多100项、2MiB、24小时，绑定凭据及资料库；离线注明上次验证时间，无法获知后来撤销，到期隐藏。重连刷新，401/403/410 清除旧缓存。分享收件、传感器补传、长期背景缓存分开管理。规则回顾是本机整理，不是手机本地大模型推理。

文字到 AudioTrack、合成 PCM、真实麦克风、真人听感分开报告。受控30分钟文字／播放检查不等于30分钟真人会话、两小时现场采集或电池续航验收。阶段签核与公共发布见日期验收报告及主计划。

Host `0.2.0-preview.2` 的 `completed.timings` 使用单调时钟，从本轮接受文字／最终转写起记录准备、资料构建与绑定、首个文本、首个完整分句、TTS首包及Host音频输出。来源检查保留次数和累计耗时，异步阶段可重叠，不能简单相加。`input_timing` 单独报告最后一次流式识别、整句复核和端点静音时长。Host PCM输出不表示手机已经可听，且不包含此前采集和网络延迟。原 `firstTextMs`／`firstAudioMs` 仍保留从回答准备开始的旧定义，跨版本比较优先使用有明确边界的新字段。

`0.2.0-preview.3` 增加有上限、只允许非负有限数值的模型计时，包括精确前缀命中、请求准备、模型加载／驻留、分析调度、首字与首段合成。Android `0.3.3` 分开记录首包接收和AudioTrack首次写入调用。语言／视觉重分析串行调度，并按角色设置驻留预算和空闲缓冲。默认会话内保留语言与声音驻留，视觉观察后解除视觉驻留并保留进程供按需使用；preview.3在最后连接结束时立即清理声音缓存和驻留；preview.7改为60秒无连接后清理，重连取消该计时。最后一个镜头会话结束后仍释放视觉进程。缓存只在内存按实际输入token匹配，不作为新记忆或新授权来源。高内存环境可用进程级 `CLAWSENSE_KEEP_VISION_RESIDENT=1` 对照全驻留，`CLAWSENSE_PARK_BETWEEN_MODALITIES=1` 另提供逐模态释放；两者都须独立测量。受控结果见[10月19日续验](../validation/p1-autonomous-2026-10-19.md)。

停止或设置变化会使仍在异步鉴权／历史检查中的旧对话失效；稍后返回的准备结果不得开始旧播报。声音停止不撤销已经交给执行端的任务。
