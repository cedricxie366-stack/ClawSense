# ClawSense v0.1.0 Beta Readiness - 2026-07-04

这份文档用于判断 ClawSense 是否可以进入第一个内测 release。它不是公开营销稿，而是给主开发线程、验收线程和发布前检查使用的真实状态表。

## 结论

截至 2026-07-04，Host / evidence / release package / 本地 ASR / 公开会议 replay 已经具备内测候选条件；最终仍未 ready 的部分是 fresh Android 真机验收。

当前状态：

- Host / fixture / video / Phase 9：ready-to-close。
- npm package boundary：通过。
- 英文 AMI 办公会议 replay：通过。
- 中文 AliMeeting 会议 ASR + replay：通过。
- 任务归属：已支持 speaker 关系字段识别“本人”，并输出“我的任务 / 他人或团队任务 / 需标注 speaker / 无明确 owner / 只是讨论”五类分桶；真实会议仍需要用户标注 speaker 才能判断第一人称任务。
- Android final gate：未通过，因为当前没有授权物理 Android 设备，且历史 live/no-arm 报告早于最新 phase report。

## 当前可作为内测候选的能力

1. 旧 Android 手机采集现实世界音频 / 图片 / 短视频 evidence 的主链路已经存在。
2. OpenClaw 聊天页可以通过 ClawSense context 获取当天 / 昨天 / 过去几小时 evidence。
3. 对话、会议、访谈类问题会优先使用 audio transcript，不再只看图片画面。
4. 本地 ASR 支持 Whisper / FunASR / hybrid 路线。
5. 中文会议场景推荐 FunASR-primary + CAM++ speaker timeline。
6. speaker 标注后，任务归属会区分：
   - speaker 是用户本人
   - speaker 是其他已知人物
   - speaker 未标注，不能判断任务是否落到用户
   - 明确指向其他团队 / 角色的事项
   - 只是讨论主题、不是任务分配
7. 视频 keyframe evidence 已支持 caption / OCR / videoRequestId 聚合。
8. 主动短视频 evidence 已有默认关闭、用户开启、冷却、上限、拥堵保护等机器门禁。

## 已知限制

- speaker diarization 是概率证据，任务归属仍依赖用户标注。
- 远场、嘈杂、距离远会影响 ASR；FunASR / Whisper 是本地免费路线，不保证云端会议纪要级效果。
- 中文 AliMeeting deep check 是 optional，不进入默认 release gate，因为公开远场 WAV 体积较大。
- 真机环境音不污染助手提问必须用 no-arm ambient 报告证明，不能只靠主观观察。
- 自动短视频不是当前默认 release 硬门槛，除非显式设置 `REQUIRE_AUTO_VIDEO_LIVE=1`。

## 下一步

1. 接入授权 Android 真机，补 fresh primary live 和 no-arm ambient。
2. 让验收线程按 `docs/agents/final-stage-live-validation-agent-prompt.md` 执行。
3. 通过 `npm run check:stage-final` 后，再决定是否打 tag / GitHub release / npm publish。
4. 内测期间继续观察真实办公会议里的 ASR 漏转、speaker 标注、任务归属和 ingest queue 背压。
