# ClawSense 测试素材调研与模拟计划

更新时间：2026-05-31

## 目标

用公开、可追溯、尽量可合法复用的长音频 / 视频素材，构建 ClawSense 的回归测试基准，减少真人全天采集的成本。

这套测试不替代真机验收，而是补齐三类能力：

- 长音频 / 多人会议 / 课堂 / 访谈视频的语义理解回归。
- `昨天 / 过去4小时 / 刚才重点 / 继续追问` 等问题的 evidence 路由回归。
- 视频片段、关键帧 caption/OCR、音频 transcript 混合回答质量回归。

## 核心原则

- 仓库不直接提交大媒体文件，只提交下载脚本、metadata、预期问题和验收 rubric。
- 优先使用官方数据集或明确开放许可内容。
- 对 YouTube / 网站视频只做内部临时验证，不把未确认许可的原始媒体放入仓库。
- 测试必须覆盖“应该回答什么”和“不能瞎编什么”。
- 公开素材验证 host 逻辑，真机播放验证 Android 数据面。

## 推荐素材池

### 1. AMI Meeting Corpus

链接：[AMI Meeting Corpus](https://groups.inf.ed.ac.uk/ami/corpus/)

适合：

- 办公会议
- 多人说话
- 音频 + 视频 + transcript / annotation 对齐
- 任务、决策、人物提及、会议重点回顾

优先级：最高。

建议测试包：

- 选 2-3 段 10-20 分钟会议片段。
- 抽取音频、若干关键帧、官方 transcript。
- 问：
  - `刚才讨论的重点是什么？`
  - `最后任务落给谁？`
  - `过去20分钟有哪些待跟进？`

### 2. ICSI Meeting Corpus

链接：[ICSI Meeting Corpus](https://groups.inf.ed.ac.uk/ami/icsi/)

适合：

- 更长、更自然的真实会议
- 多人讨论和重叠说话
- 测 speaker / diarization 的长期路线

优先级：高。

建议测试包：

- 选 1-2 段多人讨论。
- 先用于 ASR/transcript 覆盖率与时间范围问答。
- diarization 只做观察项，不作为当前 release gate。

### 3. VoxConverse

链接：[VoxConverse](https://mm.kaist.ac.kr/datasets/voxconverse/)

适合：

- speaker diarization
- 访谈 / 新闻 / 多人对话
- 检查 `speaker_1 / speaker_2` 到未来实名标注的基础质量

优先级：中高。

建议测试包：

- 用作“人物线索”专项，不作为第一轮办公/课堂主线素材。

### 4. MIT OpenCourseWare

链接：[MIT OpenCourseWare](https://ocw.mit.edu/)

适合：

- 课堂 / 学习场景
- 讲课重点、知识点、作业和概念解释
- 部分课程有视频、字幕、讲义和开放许可说明

优先级：高。

建议测试包：

- 选 1-2 段 10-15 分钟课程视频。
- 抽取音频、课件/白板关键帧、字幕。
- 问：
  - `刚才老师讲了什么重点？`
  - `有哪些概念需要复习？`
  - `帮我整理成学习笔记。`

### 5. ActivityNet Captions

链接：[ActivityNet Captions](https://activity-net.org/challenges/2021/tasks/anet_captioning.html)

适合：

- 视频片段 caption
- 时间段描述
- 视频关键帧与片段关联

优先级：中。

注意：

- 它更偏通用视频活动描述，不是办公/学习主场景。
- 可用于视频 M2 / keyframe evidence 回归，不宜作为第一内测主验收。

## 测试包格式建议

每个测试包放在 `fixtures-manifest/` 或后续独立仓库中，结构如下：

```text
fixture-id/
  manifest.json
  README.md
  expected.md
  scripts/download.sh
  scripts/prepare.sh
```

`manifest.json` 建议字段：

```json
{
  "id": "ami-meeting-001",
  "scenario": "office-meeting",
  "source": {
    "name": "AMI Meeting Corpus",
    "url": "https://groups.inf.ed.ac.uk/ami/corpus/",
    "licenseNote": "verify before redistribution"
  },
  "media": {
    "audio": "generated/audio.wav",
    "video": "generated/video.mp4",
    "keyframes": ["generated/keyframe-001.jpg"]
  },
  "expectedQuestions": [
    "刚才讨论的重点是什么？",
    "最后任务落给谁？",
    "有哪些待确认事项？"
  ],
  "rubric": {
    "mustMention": ["topic", "decision", "action item"],
    "mustNotInvent": ["names not present", "unsupported deadlines"]
  }
}
```

## 两种模拟路径

### 路径 A：Host replay

直接把素材灌入 ClawSense ingest / state，验证服务端能力。

用途：

- evidence bundle
- retrieval
- assistant/query
- media library
- followups

优点：

- 快
- 可重复
- 不依赖真机环境

缺点：

- 不能验证 Android VAD、上传队列、TTS、后台保活。

### 路径 B：真机播放采集

用电脑/音箱播放公开素材，让旧 Android 手机真实采集。

用途：

- Android VAD 分段
- 上传稳定性
- 手机端状态反馈
- TTS 交互
- Host 不可达 / token / 503 等真实问题

优点：

- 最接近真实体验。

缺点：

- 慢
- 环境噪声不可控
- 不适合频繁自动化回归

## 第一批建议测试集

1. `office-meeting-short`
- 来源：AMI Meeting Corpus
- 长度：10-20 分钟
- 目标：会议重点、任务、人物、待确认

2. `office-meeting-noisy`
- 来源：ICSI 或 AMI
- 长度：10-15 分钟
- 目标：多人重叠、低质量 transcript 下的降级回答

3. `classroom-lecture-short`
- 来源：MIT OCW
- 长度：10-15 分钟
- 目标：学习重点、概念、复习建议、笔记沉淀

4. `interview-video-short`
- 来源：VoxConverse 或可公开使用访谈素材
- 长度：8-12 分钟
- 目标：音频 + 画面混合理解，避免只看图片不引 transcript

5. `video-keyframe-ocr`
- 来源：ActivityNet Captions 或自制屏幕视频
- 长度：1-3 分钟
- 目标：关键帧 caption/OCR、视频片段回链、媒体库可见性

## Release 前验收门槛建议

第一个内测 release 前，至少做到：

- 3 个固定公开素材包可跑通 host replay。
- 2 个真实手机播放采集包可跑通 Android 端到端。
- `过去4小时 / 昨天 / 刚才重点 / 继续说 / 整理成文档` 在固定素材上有可复现表现。
- 每个测试包有 expected/rubric，能人工或半自动判断回答是否合格。
- 失败时能区分是数据没进来、ASR 没转写、时间范围错、模型没引用 evidence，还是 TTS/UI 问题。

## 下一步

1. 先由调研 agent 选出第一批 AMI / MIT OCW / VoxConverse 可下载片段。
2. 为每个片段写 `manifest.json` 和 `expected.md`。
3. 再实现最小 `scripts/replay-fixture`，把本地素材灌入 repo-local ClawSense。
4. 最后让真机通过播放采集跑同一批素材，形成 Android 端到端报告。
