## 产品目标与用户顺序

沿MIUI式路径，先服务愿意配置和反馈的资深AI用户，再扩展到高频面对面工作的专业用户，最后提供普通用户可直接使用的客户端。初期用会议、销售或展会的同一产品核心验证；医生、银行柜员等场景按具体岗位流程另做试点。

| 用户 | 交付形态 | 必须得到的价值 |
| --- | --- | --- |
| 已有Agent的资深用户 | ClawSense插件、Android App和指定伴随服务 | 现有Agent获得获准现场及数字证据，纠正和成果可跨宿主复用 |
| 有AI基础的专业岗位用户 | 同一核心、简化连接和场景配置 | 会前恢复背景，会中即时协助，会后形成实际产物，下次继续 |
| 普通用户 | ClawSense客户端、可替换的打包执行引擎和模型配置 | 一次安装完成首次有效帮助，在支持设备上提供声明的离线能力 |

插件和完整客户端共用人物、证据、权限、会话及成果协议。用户可以更换Agent、模型和设备，继续保有和导出自己的记忆。付费服务围绕易用性、可靠性、场景配置、维护和可选模型额度建设。

## 产品组成与运行职责

| 组成 | ClawSense负责 | 适配边界 |
| --- | --- | --- |
| 原生采集协调 | 麦克风和相机所有权、音画时间、有界缓冲、状态、开始和真正停止 | 复用现有Android采集及系统媒体能力，避免两个录音器争用 |
| 现场Live会话 | 听取、思考、播报、插话、取消旧轮次、断连及恢复 | 低延迟通道直接服务现场；按能力选ASR/TTS或音频模型 |
| 现场参与策略 | 明确受邀参与、观察与指令分离、公开发言和本人提示 | 人格影响表达风格，事实和权限由证据与授权决定 |
| 个人证据记忆 | 原件、分析历史、人物关联、纠正、约定、审核和下次背景 | 保留G2规则，物理和数字原件可分库存储 |
| 上下文交付 | 项目、来源、原件、成果及处理接收方范围 | MCP或宿主原生接口提供获准上下文；A2A按对方实际接口适配 |
| 工作执行 | 持久化请求、进度、取消、恢复、真实产物和回执 | 首个执行宿主优先DSH，第二验收宿主为Codex；其它宿主逐项扩展 |
| 手机和桌面入口 | 分享、预览、确认、历史问答、成果查看和离线状态 | 一台Android可测试两种角色；并发双设备能力需实际双设备验证 |
| 设备协同与手表 | 同步、冲突、删除传播、权威转移、手表收音与标记 | 当前桌面权威保留，未来手机权威通过独立迁移和同步协议建立 |

现场对话与复杂工作使用两种速度的回路：Live及时回应当前问题；工作请求进入持久化执行回路，在完成后把结果带回同一会话。两者共享授权、来源和取消关系。MCP工具发现、工作保存、实际执行、成果认可、发送和送达各有独立状态。

nanoMuse的设计参考、可选宿主和上游复用边界依据[源码与许可评估](research/nanomuse-reuse-2026-10-14.md)。原生运行时由ClawSense掌控；采用候选上游时核对具体代码、依赖与模型权重版本及分发条件。

公开执行须约束执行身份、工具和会话状态，不能仅过滤提示材料；当前Live公开场景限定本地回答，DSH任务在本人模式发起。

H的请求状态须区分排队、执行中、等待本人操作、完成、失败、取消中、已取消和中断；保存请求与宿主运行之间的关联。取消只有取得相应执行端结果才报告已取消。外部动作开放时，发送权限和实际回执单独记录；P2核心案例可用真实草稿/文件完成，不要求向客户真实发送。

I的本地收件、短时传感器补传、长期记忆缓存是不同生命周期，分别管理容量、保留和撤销。手机交互确认需有可信本人操作来源，Agent写入“已确认”不能提升确认权威。一台手机两种角色的连接不能互相覆盖。

N根据获准来源构建检索与回顾，并将摘要绑定实际输入证据与版本。旧整库摘要不能直接交给仅获准一个项目的Agent；原件到期、未决冲突和来源覆盖不足随结果说明。自然表达与人格配置不会改变事实或确认权威。

## 共同验收故事

每阶段在同一故事上增加能力，并对声明支持的设备和宿主保留实际记录：

1. 用户安装插件并配对Android，现场介绍助手，明确选择记录或Live会话；开始、采集状态和停止可见。
2. 面谈中说“周五收到方案”，镜头看到相关物件；助手引用当次声音和当前画面回答。
3. 用户插话、改口和追问，助手取消旧生成与播报；旁人普通对话和图片文字不触发执行。
4. 主手机选定客户联系人，另行确认聊天身份；分享“改成周四”的选定片段，裁剪并检查OCR。
5. 现场原话和聊天变化各有来源与发生时间。用户确认当前约定，保留收到动作、接收方和期限原词。
6. 库里同时保留私人材料；仅授权本项目给办公Agent。查询、原件、导出、模型处理和现场播报执行对应范围。
7. 用户在手机发起工作，DSH实际执行；显示真实状态，取消和重试不重复动作。第二宿主读取同一纠正和实际成果。
8. 错误稿被拒绝，正确稿由本人接受并明确替代；手机能查看正文或文件。已保存、已接受、已发送和已送达分别说明。
9. 电脑关闭或网络中断时，手机仍可查看授权缓存，清楚显示新鲜度与排队/中断；声明的纯本地能力独立完成无网检查。
10. 重连、手机重启及下次会面后恢复背景，说明现场原话、线上修改、实际工作与未完约定。
11. 来源或人物关系修改使相关成果过期。删除或撤销后，晚到分析、离线补传及客户端旧回答不继续成为可读成果。
12. P3加入手表和第二设备后重复同一故事，测收音、漏记、重复、续航和携带负担；P4由普通用户自行完成首次使用。

P1验现场连续会话与当前证据；P2验现场和数字变化到实际产物、手机查看与下次复用；P3验手机权威和多设备；P4验独立安装与声明机型能力。自动日志不能代替真人声音自然度、使用负担与画面相关性反馈。

## Live与可靠性的测量要求

以下保留初始原型目标，C/F实测后允许修订并记录原因；它们尚不是当前产品性能：

| 项目 | 初始目标及测量 |
| --- | --- |
| 结束说话到首个可听回答 | 短问答P50≤1.5秒、P95≤3秒；端点、识别、检索、模型和播放分别计时 |
| 插话到停止旧回复 | P95≤300毫秒；同时取消旧生成及全部待播，不能在安静后恢复旧答案 |
| 连续对话 | 至少10轮，保留对象与话题，覆盖短句“对/不对/停”、改口及停顿 |
| 回声与误触发 | 受控扬声器/尾音样例中零自开新回答；另测电视、旁人和背景敲击，不外推任意环境 |
| 当前视觉 | 目标帧年龄≤2秒；取不到新帧时说明过期；保留帧时间与问题时段 |
| 自然声音 | 真人分别评估可懂、连贯、自然、数字/日期/姓名读音；短答与全文分别检查 |
| 持续资源 | 先30分钟混合会话，再2小时采集；记录电耗、温度、内存、丢帧与缺口 |
| 离线与外发 | 按模式断网和检查请求记录；失败不静默转外部模型；外部处理记录实际受控接收方 |
| 恢复与容量 | 在声明缓存容量内验证断网/重启/重复/取消；超限明确记录拒绝或丢弃及缺口 |

测试固定手机、系统、App、Host、宿主、模型、依赖和样例。耳机/扬声器切换、电话中断、前后台、锁屏和网络丢失均进入对应设备清单。多人重叠和身份识别单独验证。

## 本地隐私与设备协同

三种运行模式分别声明：纯手机本地、指定自有设备协同、获准外部模型。端侧采集、端侧存储、本地ASR、手机编排和全链本地推理分别记录。自带密钥或多供应商体现选择权，处理位置由实际调用和出站检查证明。

G2提供当前来源授权、快照和删除规则。新增Live、数字来源、缓存和执行端必须复用这些语义；公开回答只读公共范围，本人屏幕/耳机和办公Agent交付分别授权。ClawSense受控SDK可记录实际供应商请求；外部Agent收到内容后的模型使用及外部副本不由服务器单独保证。

M采用手机独立存储与同步协议；跨设备使用持久标识、来源版本、幂等事件和删除墓碑，离线冲突可复核。权威转移先建立一致检查点，再切换单写入权，前滚恢复保留新事件和删除；两个程序不共写目录。新协议不把旧备份或外部副本回执伪装成已擦除。

## 用户试用与商业验证

P2目标招募5至10位已有AI基础、每周多次面对面交流的用户，连续两周；这是招募目标。以会议及销售/展会中的一个高频岗位起步，使用同一核心和共同验收故事。

衡量每周主动使用、下次复用、用户确认有用的现场帮助和实际工作成果，记录纠错耗时、无依据回答、误归属、不合时宜发言、越界交付、延迟及每次有效帮助成本。设备实验额外记录愿意携带/佩戴、收音收益和续航。连接器数量和录音总时长只作运行数据。

根据这些结果确定默认宿主、设备组合、场景包和本地模型范围；用户大量从ClawSense发起任务、现有引擎限制现场体验或普通用户需要免配置时，扩大自有harness。普通用户服务可包含安装支持、模型额度和私有部署，个人记忆与停用订阅后的访问/导出继续由用户掌控。
