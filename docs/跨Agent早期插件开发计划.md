## 当时的执行主线

长期愿景是“可信、可纠正的现实世界记忆”，逐步成为人类与 Agent 的第二个义眼，并延伸到数字世界。当前交付目标保持不变：可安装到主流 Agent 的 ClawSense 早期插件，让用户完成采集、查询、纠正、工作交接和下次复用。

旧手机的现实采集、主手机的数字上下文与随身交互、桌面与 Agent 执行，是同一个产品的不同节点。新增主手机能力必须延续现实世界语音入口、音视频证据和已有工作流，不能另建一套独立的人物、记忆与任务体系。

本文件是开发顺序与阶段验收的唯一主计划。[手机与桌面数字上下文规划](./手机与桌面数字上下文规划.md)保留输入方式、Android runtime 与平台细节，受本文件的门槛约束。旧 OpenClaw 阶段记忆与报告是历史证据，不能替代当前版本验收。

## 本次审计：此前哪里没有真正整合

此前两份规划在愿景和展会场景上有关联，执行上仍有五处断点：

1. 原“眼睛”主线的真机收音、视觉证据、TTS 和品牌客户端验收尚未闭环，D0/D1 已被列为下一开发批次；“继续推进”没有规定前置验收。
2. 宿主安装、共享工作对象、自动唤起、连续双向会话是不同能力。此前把执行路由放在较后的手机增强阶段，没有将它列为两类手机共同需要的中枢。
3. 现场人物、speaker 标注、面谈参与者和新增数字身份登记没有统一迁移与纠正协议。字段都叫 personId 不表示已经是一套身份系统。
4. 当前数字快照不覆盖物理 artifact、异步 ASR/视觉分析版本；数字作用域不表示物理读取与所有派生结果已受相同权限控制。
5. 手机缓存目前偏重数字事件，尚未缓存统一 briefing、承诺、工作成果和会话运行状态。本地收件箱还不是完整手机任务 runtime。

已写入的 D0/D1 源码保留为未验收增量，暂停新增主手机产品功能，优先完成 G0/G1。之后的共享契约工作必须覆盖两条输入路径。公共市场发布单列为交付门槛，不能遗漏，也不能用市场审核状态代替本机产品验收。

## 一个产品的职责与流向

| 节点/公共能力 | 责任 | 与其他节点的连接 |
| --- | --- | --- |
| 旧手机或兼容相机：现实之眼 | 知情采集声音、画面、短视频，保住原件、时间与缺口，接受显式语音提问 | 进入同一 workspace；提问进入统一执行入口；可承接 TTS |
| 主手机：数字之眼与随身入口 | 接收选定截图、文字和联系人，预览确认，缓存背景/工作/对话，随身提问 | 使用共同人物、项目、面谈和权限；无需持续打开相机/麦克风 |
| 桌面伴随服务 | 当前 workspace 的权威写入端；处理队列、检索、宿主连接器和工作台 | 手机离线排队后通过协议同步；禁止两个写入进程共用状态目录 |
| 共享证据与记忆 | 统一来源、人物关系、事实/承诺、纠正历史、版本、保留及权限 | 同时承接现场材料与数字片段；原件、识别、用户确认分层 |
| Agent 执行与对话 | 按用户选择调用获准宿主，维护连续会话与任务状态，保存实际产物 | 既供旧手机语音，也供主手机和桌面；OpenClaw 是首个适配 |
| 输出与下次复用 | 屏幕全文、语音短答、私密背景、成果与下一次 briefing | 公开发言和私密建议区分证据范围；草稿、发送和送达分开 |

共同闭环：

    现场声音/画面/短视频 ─┐
    主手机选定聊天/联系人 ├→ 来源与身份确认 → 获准证据和可纠正记忆
    桌面选定资料/成果 ───┘                         ↓
                                     用户指定 Agent 的对话/工作执行
                                                  ↓
                                     回答、TTS、产物与状态回流
                                                  ↓
                                     下次会面背景与未完工作

共享逻辑不要求把所有原件搬进同一个文件。物理与数字存储可继续隔离；统一的是标识、权限、证据引用、版本与消费协议。

## 必须共同定义的数据与执行契约

| 契约 | 必须解决的问题 | 当前缺口 |
| --- | --- | --- |
| workspace / device / capability | 旧手机和主手机属于哪个空间，分别获准采集、同步和读取什么 | 主手机授权初稿已有；实际双设备配对与撤销未验收 |
| person / externalIdentity / speakerLink | 现场说话人、联系人和聊天身份如何确认、撤回或拆分 | 数字登记未接通原人物和 speaker 标注；工作台仍存在同名复用逻辑 |
| encounter / project / evidenceRef | 线上变化怎样关联现场面谈并跨次查回 | 数字事件可带 sessionId/projectId，但当前主要依赖显式填入 |
| observation / analysis / correction | 原件、OCR/ASR、用户确认和相互矛盾的约定如何并存 | 两条输入路径尚无统一版本与矛盾处理；不能按导入时间覆盖聊天发生时间 |
| contextSnapshot | 工作实际用了哪些现场/数字证据及处理版本 | 数字事件与身份版本已有初稿；物理原件与异步识别版本未纳入 |
| access / retention / deletion | 列表、检索、原件、会话、结果与缓存如何一致受控 | 数字作用域不能替代物理 ACL；阻止依赖读取不等于从所有存储擦除派生正文 |
| conversation / agentRun / workItem | 手机请求如何进入所选宿主、追问、取消、恢复并回写 | 已有共享 workItem；通用自动执行和跨宿主连续会话尚未实现 |
| outputAudience / artifactReceipt | 给本人看或当众说，已生成或已发送，怎样准确区分 | 缺统一公开/私密输出策略与真实执行回执；TTS 回调不证明听感通过 |

上述对象是后续设计与实现任务，不代表当前代码已经具备。迁移必须保留 Android ingest 与 OpenClaw 入口，不能为了统一概念破坏当前数据面。

## 开发顺序与硬门槛

门槛通过要求当前版本对应的实际证据。依赖未通过时，可设计契约、补测试素材、准备包与文档；不能继续扩大后续产品功能或宣称阶段交付。

G2准备可包括独立的类型草案、只读盘点和纯规则原型，在合成数据/离线副本中检查；不导入运行入口、不改当前授权默认值、不迁移活跃资料库。这类准备不要求用户立即进行G0/G1验收，完成后状态记为“准备完成、待接入”，不记为G2通过。

| G5 分发收口与扩大覆盖 | 版本包、首装/更新、支持矩阵、发布资料、公开分发及市场提交；补其余宿主，按需求推进桌面 D2 | 对外宣称功能均通过对应门槛 | 实际安装版本/入口可核验；逐宿主/市场标明已验证、待验证或待审核；本地打包不算公开发布 | 本地包安装已验证；本轮跨 Agent 预览尚未公共发布或市场签核 |

G0/G1 先建立“旧手机＋实际 Agent”基线，不要求先买第二台手机。G4 可先在一台 Android 上分别测试两种角色；并发双设备、权限与离线同步须有两台实际设备才可签核。

市场资料、平台接入条件和包准备可前期并行整理；公开发布另行记录实际结果。G4 不必等待所有平台完成外部审核，但不能因此将 G5 标为完成。

## 联合验收场景

各阶段围绕同一展会客户场景增加能力，不能各挑容易通过的演示。

1. **现场留下依据。**旧手机知情记录“客户希望周五收到方案”及相关产品画面，原件可回查；缺口与识别不确定项可见。
2. **确认同一个人。**用户确认现场参与者，再将选中的通讯录联系人明确关联到该人。同名人物保持独立，微信身份单独确认。
3. **补入线上变化。**主手机分享“改成周四”的片段，区分聊天发生时间与分享时间；展示两条依据，由用户确认当前约定。
4. **两个实际 Agent 使用一致上下文。**A 读现场＋线上获准材料，用户纠正归属；B 重新读取最新确认。未授权项目不可读。
5. **真正执行并回流。**用户指定 B 制作跟进方案。G1 证明真实宿主执行并手动回写；G3 证明请求可自动调用宿主、维护状态并回写。正文/文件可打开，失败、取消与重试可识别。
6. **随身连续交互。**主手机问“截止时间改了吗”，答案引用两类来源；私密内容不进入当众播报。桌面离线时可查看缓存并识别新鲜度。
7. **下一次继续。**重启后查看现场内容、线上修改、已完成方案与未完工作。修改源证据或身份关系使相关成果过期；删除/撤销不被离线队列复活。

G0/G1 先验收可成立的现场与插件路径；G4 必须完整通过七步。持续录屏、主动联网插话、自有完整 harness、手机独立权威存储和新硬件属于增量，不替代此闭环。

状态分为设计、源码实现、构建/协议通过、真机通过、实际宿主通过、联合场景通过、公开分发/市场状态。后一种状态不能从前一种推定，也不用笼统的“支持”覆盖差异。

对外版本列明真实支持范围。缺模型环境或平台接入时记录对应阻塞，其余打包、文档和独立验收继续。公开发布的版本、下载入口、安装回执与市场审核分别留下证据。

## 长期扩展与架构约束

- Android 主手机优先，复用 APK；采集连接和主手机连接分别保存，共享 workspace 和业务对象。
- 默认本地优先；采集、保留、处理、Agent 读取、联网交付和公开发言分别授权。本地 ASR 不表示全链本地。
- 手机通过持久化事件/任务协议同步；每个 workspace 初期只有一个权威写入端，禁止双向覆盖 JSON。
- 保留原 audio/image/video ingest、OpenClaw 入口、已有素材与标注。
- 原件、识别、人工更正分别保留版本。图像/视频理解与声音识别均属于“眼睛”质量，不被主手机 OCR 替代。
- D2 桌面网页/文件及成果、D3 受控屏幕采集、D4 端侧推理与有限自主任务，在 G4 后分批推进。用户指定宿主执行和双向会话已提前到 G3。
- 截图不证明完整聊天历史，联系人不证明微信身份，草稿不证明已发送。
- 权限覆盖所有读取和输出；外部 Agent 已复制内容不能承诺自动全部擦除。
- Runtime 资产放 agent-plugins/，开发指导留 AGENTS.md 和 .codex/，不进入用户运行技能。
