## 5. 当前验证口径

代码侧最小验证：

```bash
npm run check
npm test
npm run check:release
```

当前阶段一键验收：

```bash
npm run check:phase
```

`check:phase` 会顺序执行 release gate、Android debug build、AMI 办公会议 replay、MIT 课堂 replay、MIT 课堂视频 replay、AMI speaker 标注 smoke、`hostModelVideoMode=keyframes`、`acceptance 5/5` 和视频 evidence transcript/keyframe 断言。默认只记录 Android 设备是否在线；如要把真机在线也作为硬门槛，执行：

```bash
REQUIRE_ANDROID_DEVICE=1 npm run check:phase
```

Android 真机辅助门禁：

```bash
npm run check:android-live:doctor
npm run check:android-live:fixtures
npm run check:android-emulator:smoke
npm run check:android-live
scripts/check-android-live.sh arm-query auto
PRESERVE_LOGCAT=1 scripts/check-android-live.sh arm-query meeting
PRESERVE_LOGCAT=1 scripts/check-android-live.sh stop-tts
PRESERVE_LOGCAT=1 scripts/check-android-live.sh capture-video
HUMAN_TTS_OK=1 HUMAN_ANSWER_RELEVANT=1 scripts/check-android-live.sh collect
scripts/check-android-live.sh observe-ambient
EXPECT_NO_ASSISTANT_QUERY=1 scripts/check-android-live.sh collect
```

`check:android-live:doctor` 是非破坏性 preflight，会生成 `.local/android-live-reports/preflight-*.json`，用于确认 ADB、debug APK、repo-local OpenClaw、current-phase report 和最新 live report 状态。它不会安装 APK 或启动服务；如果只剩设备缺口，状态应为 `waiting-for-device`。报告里的 `emulatorDebug` 会列出本机可用 AVD 和可选调试命令，但 `emulatorDebug.canSatisfyFinalGate` 必须是 `false`：模拟器只能调试安装 / 配对 / 服务启动，不能作为当前阶段最终通过证据。

preflight 中的 `latestAndroidLive` 和 `latestAndroidNoArm` 是两份不同报告：前者必须证明正常语音问答 / TTS / 手动视频，后者必须证明无提问环境音不会污染显式提问。即使 no-arm 报告更新，也不能被当作正常 live 报告。

`check:android-live:fixtures` 使用合成 logcat / devices / media / evidence / package 输出验证 live report 汇总器，确保 `voiceLoopObserved`、TTS、`audioRecheckAttempted`、视频上传、物理设备判定和 APK 版本字段不会被日志文案或解析逻辑改坏。它同时覆盖几条不能误判为通过的负向路径：缺少人工 TTS / 回答相关性确认、模拟器伪装物理设备、HTTP 401 鉴权失败、缺少 audio recheck 诊断、无提问环境音被误判成 assistant query。它不替代真机验收，只保护 live report 生成逻辑。

`check:android-emulator:smoke` 是模拟器专用的安装 / 配对 / 服务启动烟测：它会把报告写到 `.local/android-emulator-smoke-reports/`，并强制断言 `androidDevice.isEmulator=true`、`verdict.physicalAndroidDevice=false`、`verdict.phaseReadyForRelease=false`。这条命令只用于提前发现 APK 安装、debug receiver、ADB reverse、UI 启动等工具链问题，不能替代真机验收。

当前阶段最终硬门槛：

```bash
npm run check:stage-final:fixtures
npm run check:stage-final:doctor
npm run check:stage-final:index
npm run check:stage-final
```

正常 primary live report 必须在同一个 logcat 窗口里累计“语音问答 + TTS completed + stop-tts + video upload”。因此第一轮 `arm-query` 默认清空 logcat，后续 `arm-query meeting`、`stop-tts`、`capture-video` 应使用 `PRESERVE_LOGCAT=1`；否则会生成多份各自只证明一部分的报告，`check:stage-final` 会选择最新 primary report 并正确判失败。

对语音依赖问题，live report 还会记录 `verdict.audioRecheckAttempted` 和 `verdict.audioRecheckRefreshed`。如果目标窗口里仍有待转写音频，但这两个字段一直为 `false`，说明实时语音入口没有真正走到音频补强链，需要优先排查。

`check:stage-final` 不替代验收，而是审计最新报告：它要求 `check:phase` 的 Host / fixture / video evidence 已通过，同时要求最新 Android live 报告证明 voice loop、TTS、人工听感确认、停止朗读、手动视频上传与 host evidence 都成立，并要求一份 fresh `EXPECT_NO_ASSISTANT_QUERY=1` no-arm 报告证明“播放访谈 / 视频但未点击问实时助手”不会产生 assistant query。没有真机报告或没有 no-arm clean 报告时它必须失败，不能把 Host 侧绿灯误写成整阶段完成。
