# ClawSense 当前阶段交付收口清单

更新时间：2026-05-30

## 1. 当前目标

当前阶段的交付目标不是继续无限扩功能，而是把已经完成的大量改动整理成一个可审查、可验证、可发布的阶段版本。

当前产品目标保持不变：

- ClawSense 是 OpenClaw 的现实世界语音入口。
- Android 旧手机负责持续采集现实世界音频 / 图片 / 后续视频。
- Host 插件负责 ingest、媒体库、evidence、检索、主模型回答、验收矩阵。
- OpenClaw 主模型基于 evidence 与用户自然对话，而不是让插件提前把所有内容总结死。

当前代码收口目标：

- 把巨大 dirty worktree 拆成可 review 的交付批次。
- 明确哪些已经代码完成，哪些仍需要真人验收。
- 明确下一阶段进入 Android 视频 M2 前的决策点。

## 2. 当前 worktree 状态判断

当前 worktree 不是普通小修，而是一个阶段性产品包，覆盖：

- Host runtime 核心
- Android 语音助手客户端
- 本地 OpenClaw 开发 harness
- 文档与验收 agent
- 测试矩阵
- 安装 / 发布配置

因此后续提交时不建议“一口气全量提交”，而应按下面交付批次拆分。

## 6. 下一步建议

当前第一优先级：

1. 按 Batch A-E 做分批 review / commit。
2. 每个 batch 至少带对应测试结果。
3. 完成后再决定是否进入 Android 视频 M2。

Android 视频 M2 的决策项：

- 是否引入 `androidx.camera:camera-video`。
- 短片段时长：建议 10-15 秒。
- 关键帧间隔：建议 3 秒。
- 上传频率：建议低频、事件触发，不做全天连续录像。
- 隐私提示：必须在 UI 和文档中明确。

一句话收口判断：

> 现在最重要的不是继续加能力，而是把已经做出的“语音入口 + evidence 回答 + 视频关键帧证据链”整理成一个可审查、可发布、可验收的阶段版本。

当前明确需要用户拍板的动作：

- 是否按 [当前阶段分批提交计划](./当前阶段分批提交计划.md) 创建正式 git commits。
