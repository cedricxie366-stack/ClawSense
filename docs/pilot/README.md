# ClawSense 专业场景内测候选版

2026-10-16；Host `0.2.0-preview.2`，Android `0.3.0-live-work-preview`。这是集中体验前的候选包，尚未公共发布。使用边界见[支持范围](support-matrix.json)，开发与验收状态以[主计划](../产品演进路线与执行计划.md)和[收尾记录](../validation/p1-p2-closeout-2026-10-16.md)为准。

## 第一批解决什么问题

面向已有 AI 使用基础、经常与客户面谈的人。围绕一个客户的四次动作：见面前回顾，现场受邀回答，会后把选定资料交给 Agent，下一次交流继续使用。首批目标5至10人、两周，当前尚未招募。集中体验通过后再逐个邀请；不把一次演示当作持续使用证据。

基础 Live 需要 Android 和一台已配置模型的 Apple Silicon Mac。手机采集、控制、播放，Mac 识别、推理和合成；手机另有本机 OCR、裁剪和遮挡。复杂任务按授权交给 DSH／Codex，其实际模型可能使用外部服务。纯手机完整推理和任意 Agent 自动接入尚未交付。

## 安装与首次使用

首批采用协助安装，仍需自备电脑运行环境、模型文件，以及所选 Agent 的登录或模型配置。现有环境中的干净目录安装已经检查；尚未证明每位新用户可以独立完成首装。

1. 从同一候选发行包取得 `.tgz`、独立 ClawSense Live APK、校验清单及本手册。保留旧客户端与旧资料，先用新的资料目录测试。
2. 电脑准备 Node.js 22.12 或更新版本、Python 3.12 与 uv。将安装包复制到新的内测目录。下面命令中的安装包路径、IP及端口按当前电脑填写。

```sh
npm install /安装包所在目录/clawsense-0.2.0-preview.2.tgz
python3 node_modules/clawsense/scripts/live/prepare.py \
  --state-dir ./live-env --lan-host 电脑的局域网IP \
  --port 19611 --live-port 19612
./node_modules/.bin/clawsense live-serve \
  --state-dir ./live-env/state --config ./live-env/config.json \
  --host 0.0.0.0 --port 19611
```

首次准备会下载指定模型和依赖，需要网络、时间与磁盘空间；密钥、个人资料和模型不随候选包提供。已准备的基础模型运行不自动回退云服务。当前模型组合实测电脑为 M4／16GiB，不据此声明所有电脑配置可用。

3. 保持服务运行，在另一个终端进入同一内测目录，生成采集手机配对码：

```sh
./node_modules/.bin/clawsense pair --state-dir ./live-env/state
```

安装并打开独立 ClawSense Live，按界面授权并配对。主手机的数字资料入口另行配对；使用同一服务生成 `pair --role primary --state-dir ./live-env/state` 的配对码。相机按需勾选。设置和查看资料不会自动开启收音。

4. 先核对本人／公开场景和资料的处理位置，再开启 Live。先叫助手名字，随后可连续追问；结束时停止服务。资料、草稿和事实需要分别确认，助手保存了内容不代表已发送给客户。
5. 接入已有 Agent 时，分别生成其安装指引，再按生成目录里的说明配置。新宿主先只用合成材料检查。

```sh
./node_modules/.bin/clawsense connect codex --context-project live --context-processing selected-external --out ./codex-install --state-dir ./live-env/state
./node_modules/.bin/clawsense connect dsh --context-project live --context-processing selected-external --out ./dsh-install --state-dir ./live-env/state
./node_modules/.bin/clawsense doctor --state-dir ./live-env/state
```

这些命令先授予`live`项目的读取范围，来源也必须允许相应接收方。桌面连接器`dsh`／`codex`与手机执行端`live-dsh`／`live-codex`是分别授权的身份，不自动互换；由负责人核对需要交付的来源，工作写回能力另行配置。手机内直接派发工作的执行端另需在 Live 配置中设置。DSH 独立配置可用随包提供的 `scripts/live/dsh-prepare.mjs` 辅助，输入为已有 DSH 安装目录及模型配置。只引用私有凭据文件，不把密钥写进反馈或聊天。Codex 使用已有登录；需要代理时仅为该执行进程配置。`doctor` 只证明连接，实际文件回流和模态能力另验。

## 使用中需要看得懂的状态

- 工作显示排队、执行、等待本人操作、中断或完成；不确定时先核对，重复点击不能用来证明完成。停止朗读不会取消任务。
- 后来启用外部 Agent 不会追溯扩大旧来源的权限。历史只允许自有设备处理时，相关工作会被拒绝；当前候选版需要在来源和接收方设置核对授权，尚不能自动从混合历史中挑选一个可外发子集。首批部署时先选定处理边界。
- 成果先复核；拒绝错误稿、接受替代稿后，下次复用只使用当前已接受成果。数字资料的 OCR、人物关系和约定分别确认。
- 电脑离线时可查看最近获准缓存，最多100项／2MiB／24小时。离线无法知道后来发生的撤销；到期隐藏，重连刷新。这不是离线 Live 推理。
- 当前画面只按本轮请求取新照片；两帧比较只说明可见状态差异。没有清晰新图时，应说明缺口。
- Live 连接失败或音频被占用时，应停止相应会话并显示状态。恢复后自行开启；不要把连接中断当作工作已经取消。

## 两周怎样试

按[同一客户的试用故事](scenario.md)开始。第一天完成配对和一次合成闭环；第一周用于实际获准的面谈，第二周重点验证下次复用及更正后的行为。记录一次帮助有没有节省回忆、纠错或交接的成本。

[使用反馈](feedback.csv)和[参与者进度](cohort.csv)默认为空，由内测负责人保存在自己的设备。用代号即可，不默认收集客户姓名、聊天原文、音视频或密钥；没有自动上传或后台招募。自愿提供日志时先检查并删去私密内容。需要共享原件时，另行明确具体范围。

每周查看：主动使用、下次复用、本人认为有用的现场帮助、可用成果，以及纠错耗时、错误归属、无依据回答、误发言、延迟和有效帮助成本。人数和录音时长不能替代这些结果。

## 升级、停止与问题反馈

本次 Host 更新保持原 Android ingest、OpenClaw 和资料格式；更新前停止对应服务并备份自己的状态目录，升级同一内测安装目录里的包，再用同一配置启动。一个资料目录只运行一个写入服务；不要复制运行中的目录作为第二个服务。版本回退不替代资料恢复，备份恢复应进入新的目录并单独核对。

停止 Live 后确认麦克风／相机状态结束。反馈按 CSV 记录实际表现和版本；需要复现时先用合成客户材料。耳机、来电、真机锁屏、长时间采集及自然听感仍有集中验收项，不能由模拟器结果外推。
