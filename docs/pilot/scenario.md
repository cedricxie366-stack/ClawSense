# 同一客户，两次见面的试用故事

先用合成客户“小陈”，再由内测用户选定已获准的实际场景。每个环节记录实际看到的结果和是否需要额外解释，不真实发送给客户。

1. 见面前，查看该人物／项目的背景、未完约定和已接受成果。没有材料就承认缺口。
2. 介绍助手，选择记录范围及本人／公开场景。说“小陈希望周五收到方案，预算三万元”。邀请助手回答期限，并核对来源。
3. 连续追问、改口并插话。说“停”或按停止后，旧声音应停止且不会自行恢复；背景闲谈不自动派发工作。
4. 主手机分享合成聊天片段“改为周四收到方案，预算四万元”。裁剪／遮挡，检查 OCR；人物关联与当前约定由本人分别确认。
5. 发起一份草稿，让 DSH 实际生成文件；核对正文和状态，再让 Codex 使用同一份已确认约定处理另一份草稿。错误稿拒绝、正确稿接受，并明确替代关系。
6. 手机上查看成果，断开连接查看获准缓存，再重连。只核对声明的缓存能力，不把它当作完全离线模型。
7. 下一次见面，先问“上次约定了什么，哪些还没完成”。应区分现场原话、聊天修改和已接受成果。更正或删除后，旧答案不能继续充当当前事实。

一次成功后至少跨天再试一次。第二次是否真正用上，和第一次演示是否跑通分别记录。核心真人验收见[集中清单](../validation/p1-p2-human-acceptance-2026-10-15.md)。
