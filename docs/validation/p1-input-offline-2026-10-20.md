# P1 输入诊断与纠错：断开手机后的独立开发

日期：2026-10-20（Asia/Shanghai）。依据[现行计划](../产品演进路线与执行计划.md)及[本轮真机记录](p1-human-2026-10-20.md)，附[结构化台账](p1-input-offline-2026-10-20.json)。用户暂缓真人验收并断开手机；已停止独立验收服务，保留配对和资料，不再启动麦克风、相机或播放。公共发布／招募继续暂缓。

## 交付与适用范围

离线候选为Host `0.2.0-preview.6`、Android `0.3.6-live-input-preview`／versionCode10。新的APK尚未安装到小米；最后实际手机版本仍为0.3.5／versionCode9。本人已接受的三段短句声音属于Host0.2.0-preview.5及该真机版本，不被本轮软件检查扩大为整阶段验收。

- 每句语音有递增输入编号及处理回执：识别中、已接收、等待点名、环境话语忽略、回声忽略、过短／过长、无有效文字、被新操作取代、停止请求已处理或处理失败。“已接收”表示进入对话处理，不等于记忆已确认或工作完成。
- 保留接收帧数、VAD阳性帧、输入峰值、语段缓存／有声／静音毫秒、队列和结果计数。约每秒向已认证设备发送一次数值健康信息，即使没有形成完整一句也能区分传输与收句状态；可在收音异常时主动复制诊断。诊断不含识别正文、凭据或音视频原件。
- 两种整句识别不一致时向同一设备提供最多400字符的备选，不等待较慢的识别器才回答。备选只在界面暂存，不写入历史、事实或确认记录，不交给语言模型，也不自动把“IP排”替换为“安排”。新输入、重连与来源失效会淘汰不再适用的结果。
- 手机可修改识别文字或备选，再作为一个新问题发送。原历史不改写；该操作不提升本人确认权威。接收方、公开场景、宿主工具与来源权限仍走原检查。

本轮没有调整原Android ingest、OpenClaw入口、TTS音色／采样、原始声音或VAD算法。新事件为兼容扩展，旧客户端可以忽略；新客户端连接没有这些事件的旧服务时仍保留原文字问答。

## 检查结果

516项项目检查通过；54项Android JVM及Live预览构建通过，APK签名验证通过。跨Agent检查、stdio流程和3项校准通过，均不替代真实宿主或Android验收。新检查覆盖迟到旧输入、备选不入库、不自动改写识别、来源失效后不泄露备选、空输入／短句、回声、快速停止竞态及按秒数值诊断。

一次默认高并发全量检查中，原有数字HTTP用例超过5000ms，已保留失败日志；该文件单独检查通过，随后限制四个并发worker的完整516项检查通过，没有修改每项时限。原生手机新界面没有由此获得实测结论。

## 实际识别模型的受控回放

使用此前生成的六秒语音“会议安排在明天下午四点，预算五万元，方案周六交付”，在隔离状态中经实际Silero、Paraformer和SenseVoice处理。对话答复为受控夹具，没有调用真实语言／语音生成模型、没有手机麦克风或扬声器，也没有更新原验收资料库。

| 输入 | 限定结果 |
| --- | --- |
| 原幅度语音 | 单一语段保留四点／五万元／周六 |
| 幅度缩放为15% | 单一语段保留相同三事实 |
| 人工在中点插入500ms静音 | 单一语段保留三事实；出现“预预算”的重复识别，不称逐字准确 |
| 静音、低幅白噪声、120Hz模拟风扇、短促模拟敲击 | 四组均没有触发对话答复，且没有处理错误 |

这些是七个生成材料案例，不是实际房间噪声、真人ASR准确率、人声时延P95或全天可靠性结论。“IP排／安排”的真实声学错误因没有原始Live录音，仍未复现；相应备选保护使用受控不一致夹具验证。

## 保留的失败与判断修正

最初低音量回放只附加1.4秒末尾静音，没有形成完整输入。进一步计数证明声音确实进入VAD：164帧阳性，语段有声3280ms，但停止送帧时只累计740ms连续静音，低于当前安排陈述的1100ms收句条件。墙钟等待不会替代持续送来的声音帧。补足末尾声音后，未改动的原VAD也通过该案例。

曾试验有界增益，未得到必要性证据；已撤回，最终worker与实验前文件SHA256完全相同。最初“VAD完全没检出”的推断已更正，失败和增益对照不改写为成功。不能据此认定此前真人漏句的实际原因已经找到或修复。

原始记录及生成材料在私有`.local/p1-input-offline-2026-10-20/`。原10月19日综合候选及本轮已验声音版本不覆盖。
