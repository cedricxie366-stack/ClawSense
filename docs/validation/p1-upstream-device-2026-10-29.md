# P1 上游 Live 真机接入续验

日期：2026-10-29，Asia/Shanghai。设备为已授权的 OPPO Find X2（PDEM10／Android13）。Host沿用 `0.2.0-preview.11`，Android已保留资料升级至 `0.3.12-upstream-device-preview`／versionCode16；安装文件与手机上的APK哈希一致。

**已完成安装、独立服务配对、官方SDK连接与文字问答，以及最终界面准备。正式听感、真实收音、声学回声和实物检查集中留给最后一轮；P1未整体签核。** 原验收候选与日期记录保留，不把新证据写回旧版产物。

## 已确认的结果

- 手机与Mac在同一局域网，路由直接走无线网卡；VPN保持原状。USB承担HTTP信令转发，官方SDK的WebRTC连接实际建立成功。
- 官方SDK收到“七加五是多少”的文字答案“结果是12。”，首次就绪样本16469ms。测试明确禁止语音输出，TTS及播报事件均为0，本地发布的音频／视频轨道均为空。
- 配对在覆盖安装和进程重启后仍可使用。原设置已私有备份，应用数据没有清除。
- 后续改为只调用HTTP模型准备，不创建RTC或传感器连接。准备样本14623ms，旧Live未连接、输入帧为0；系统麦克风和镜头访问时间没有因此新增。
- 0.3.12增加显式Live期间保持屏幕亮，结束／离开时清除，避免桌面免手持对话被自动熄屏截断。用户主动锁屏仍按原生命周期结束会话。
- 56项Android JVM检查及候选／测试包构建通过。已核对“进入 Live 对照版”“尚未开启”“开启 Live”界面，未替用户点击开始。

## 自动检查中的硬件访问例外

初次接收连接测试虽然关闭了SDK音轨发布，Android系统仍记录约5362ms的麦克风访问。这证明“没有发布音轨”不能当作“硬件麦克风没有被访问”。本次没有语音输出；服务保存的观察只有预期的两条文字测试问题，没有额外观察内容。

随后尝试在系统层禁用测试应用麦克风，OPPO以缺少 `MANAGE_APP_OPS_MODES` 权限拒绝。命令没有修改原允许状态，但原串行脚本继续进入了复验；发现后立即强制停止应用，系统另记约19ms访问。此复验记为中止，不计通过。之后没有再自动创建手机媒体连接。

已给接收连接测试加上系统麦克风权限必须处于拒绝状态的前置断言，防止以后仅凭轨道标志继续运行；当前设备保持用户原有权限。剩余自动准备只使用HTTP接口。最后检查时采集服务为空，麦克风无运行中访问，镜头访问仍是旧日期记录。

## 最后集中检查

由本人手动勾选镜头并开启新版Live，等到聆听状态后，连续核对一条安排、一次改口、眼前实物、长答中说“停”和随后恢复问答；每次先等回答完整结束。最后结束Live，反馈完整性、自然度、内容正确性和停止后的状态。

本轮自有Mac处理，开启后最多两分钟停止。若屏幕已熄灭，可正常解锁后进入ClawSense Live；不得绕过设备锁屏。当前仍保留原计划中的完整十轮、复杂设备组合、持续资源及延迟统计退出条件。
