# ClawSense 当前阶段正式收口总结

这份文档用于正式收口当前阶段，明确：

- 我们已经完成了什么
- 哪些能力已经真实可用
- 哪些问题已经不再是主阻塞
- 哪些问题仍然存在
- 下一阶段最应该继续打的点是什么

## 1. 一句话结论

ClawSense 当前阶段可以正式收口。

项目已经从：

- 主链路能跑，但语义经常退化成 `unavailable`

推进到了：

- Android 真机采集、配对、上传、心跳稳定成立
- 后端事件索引、媒体库、`context`、`review` 数据面成立
- `Round-4 P0` 已通过真实验收
- 图片主多模态分析已在真实环境中成功
- 音频在 `runtime STT` 空结果时，已能给出保守语义，而不再普遍落成 `speech transcription unavailable`

当前还不能说它已经达到“所有 provider / 所有部署都天然开箱即用”的标准化产品状态，但已经可以明确说：

- **链路已通**
- **语义主链已成立**
- **当前阶段的主目标已经完成**

## 2. 当前阶段已经正式成立的能力

### 2.1 Android 端

已经验证成立：

- 真机扫码配对成功
- 长期 `deviceSecret` 持久化成功
- 前台感知服务启动 / 停止成功
- 状态卡可正确显示：
  - 未配对
  - 启动中
  - 运行中
  - 已停止
  - 异常
- 音频上传成功
- 图片上传成功
- 心跳上报成功
- 最小重试队列生效
- 最近活动 / 最近错误 / 待补传数量已进入 UI
- 长对话分段已通过真机验证
- `csAudio:v2 session / segment / boundary / capturedAt` 已稳定写入

### 2.2 OpenClaw / 服务端

已经验证成立：

- `openclaw clawsense pair`
- `openclaw clawsense devices`
- `openclaw clawsense media today`
- `openclaw clawsense review today`
- `openclaw clawsense context last-hour`

并且以下能力已经成立：

- 原始素材入库
- 事件索引
- 事件窗口归并
- Daily Review 生成
- 原始感知浏览面
- 普通聊天未来可消费的 `context` 数据面
- `csAudio:v2 session` 已成为更强的会话窗口依据

### 2.3 媒体库

媒体库已经不再被 OpenClaw 控制聊天页壳子接管，当前正确入口是：

```text
/plugins/clawsense/library
```

这代表下面这条产品约束已经落实：

- 媒体库复用用户当前 OpenClaw 的同一主机地址
- 不依赖 ClawSense 官方公网域名
- 不要求用户自行配置域名 / 反向代理
- 页面本身是独立轻量页

### 2.4 语义能力

这一项是本阶段最关键的新变化。

真实验收已经确认：

- 新图片事件已能稳定得到主多模态视觉摘要
- 新音频事件在 `runtime STT` 空结果时，已能得到保守中文理解
- 新事件的 `analysisProvider / analysisStatus / analysisFailureReason` 已可观测

这意味着：

- Round-4 已经不是“只把失败变得可解释”
- 而是已经把真实语义链条接起来了

### 2.5 对外发布

已成立：

- GitHub 仓库已公开
- npm 包已发布
- README / 部署文档 / Android 文档 / agent 文档 已齐备

## 3. 当前阶段已经确认的产品判断

### 3.1 主技术路线

当前全项目统一口径是：

- **推荐使用由原生多模态大模型驱动的 OpenClaw**
- 多模态模型是主分析引擎
- `runtime STT` 只做兜底
- ClawSense 保留自己的 ingest / event / review 数据面

### 3.2 当前对“多 provider / 多模型”的真实判断

模型名多样不是当前主问题。

当前真正需要被标准化的，是：

- provider 元信息如何被发现
- OpenAI-compatible endpoint 如何被表达
- 当 OpenClaw runtime 没有稳定 provider map 时，ClawSense 应如何拿到可用 client

当前最稳的现实结论是：

- **对开源用户，插件级显式 `openaiApiKey/openaiBaseUrl` 是目前最稳的跨部署配置方式**

### 3.3 媒体库定位

媒体库是：

- 原始感知浏览面
- 用来确认今天采到了什么
- 用来回看某个时间点的音频 / 图片

媒体库不是：

- 最终回顾页
- 完整私人助理总结页

### 3.4 Daily Review 定位

Daily Review 现在已经可用，而且输入语义质量较前阶段已有明显提升。

它现在适合作为：

- 产品主链路验证入口
- 早期功能展示入口
- 对外演示时的“当前可运行效果”

它现在仍然不应被误判成：

- 所有部署上的最终 polished 助理体验

## 4. 当前阶段真正解决掉的关键问题

### 4.1 配对 / 运行状态不清楚

现在用户已经能明确知道：

- 是否已配对
- 服务是否真的启动
- 服务当前是否在运行
- 最近上传是否发生
- 最近错误是什么

### 4.2 媒体库不该走 Control UI

这个问题已经被明确并修正：

- 旧实现会被 Control UI 聊天壳接管
- 现实现已改为独立轻量页

### 4.3 retention 旧迁移 bug

已修复：

- 旧 `journal -> artifacts/events` 迁移时，原件被错误地立即判过期

当前正确策略是：

- 原始素材默认保留 `7 天`
- 同时受默认 `2 GiB` 原件软上限控制
- 超限时最早原件先删除
- 事件索引与 review 保留

### 4.4 长对话连续会话线索未被真正消费

这个问题已经被 Round-4 解决到可接受状态：

- Android 已稳定写入 `csAudio:v2` 连续会话线索
- 后端已按 `session` 强化合窗
- `context last-hour` 已能形成更干净的 `audio-session::<device>::<session>` 窗口

### 4.5 图片 / 音频主多模态分析真实不可用

这也是本阶段最重要的实质性进展：

- 图片已从大量 `visual summary unavailable` 转为真实成功摘要
- 音频已从大量 `speech transcription unavailable` 转为保守中文理解
- 真实环境中暴露出的 provider 路由与配置问题，已经被定位并给出稳定配置方法

## 5. 当前阶段仍然存在的问题

这些问题已经不再阻塞当前阶段收口，但会成为下一阶段的主矛盾。

### 5.1 语义质量虽然成立，但仍然不够“强助理感”

当前音频已经不再大面积 unavailable，但在弱音频场景下仍可能只给出非常保守的结论，例如：

- “音频内容不清晰，无法准确识别具体讨论话题……”

这说明：

- 主链已成立
- 但表达强度和信息密度还有提升空间

### 5.2 多 provider 部署标准化仍不足

当前最真实的问题不是“不能接第三方模型”，而是：

- 不同 OpenClaw 部署暴露 provider 信息的方式不一致

所以现在的准确结论是：

- ClawSense 已支持多模型 / 多 provider
- 但还没有完全做到“不同部署天然零适配开箱即用”

### 5.3 普通聊天页尚未完成端到端体验闭环

当前已经具备：

- `context` 路由
- `context` CLI
- skill / tool 入口思路

但还没有完成：

- 宿主聊天页中，普通用户一句自然语言就稳定触发 ClawSense 上下文能力的完整闭环验收

### 5.4 人物 / 项目标注闭环仍然偏轻

当前已经有最小人物标注入口，但：

- 项目 / 主题的持续追踪还不够完整
- review 的人物与项目记忆闭环仍偏早期

## 6. 当前阶段的正式评估

当前项目应该被准确描述为：

> 功能链路完整，媒体库独立，review/context 可用，Round-4 语义主链已成立，但开源部署标准化与助理表达强度仍需下一阶段继续补。

也可以更具体地说成：

- **链路层：通过**
- **交互入口层：通过**
- **媒体库层：通过**
- **Review / Context 数据面：通过**
- **Round-4 语义主链：通过**
- **多 provider 标准化：未完成**
- **P1 产品闭环：未完成**

## 7. 当前最推荐的用户路径

当前最合理的使用方式是：

1. 在 Android 端启动感知服务
2. 打开媒体库确认当天是否采到足够素材
3. 运行：

```bash
openclaw clawsense review today
```

4. 如果需要更近时段的上下文，再运行：

```bash
openclaw clawsense context last-hour
```

5. 如果某些人物或项目不清楚，再补人物 / 主题信息

## 8. 当前阶段收口后的优先级

当前阶段结束后，项目优先级应切换到：

### P1

1. 普通聊天页正式接入 ClawSense skill / tool / context
2. 人物 / 项目最小标注闭环
3. 用“值得留意的社交线索”替代心理学式结论
4. 开源部署的 provider 标准化与配置模板固化

### P2

- Mac 客户端
- 官方控制面兼容
- 更重的 Web 回顾页

### 明确不建议回头重做

- 不要回头把主精力放回“打通链路”
- 不要回头把 round-4 再理解成“只是 fallback 文案问题”
- 不要因为当前支持多模型，就误判为标准化工作已经完成

## 9. 当前阶段收口后的最终判断

到当前为止，可以给出正式结论：

- 当前阶段可以正式结束
- `Round-4 P0` 可以正式收口
- 下一阶段不再以“打通链路”为主
- 下一阶段应以“P1 产品闭环 + provider 标准化”为主

最准确的一句话是：

**ClawSense 已经从“链路打通型 MVP”推进到“语义主链成立的可运行产品原型”，下一步该补的是开源标准化和更完整的助理产品闭环。**
