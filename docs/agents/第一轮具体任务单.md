# ClawSense 多 Agent 第一轮具体任务单

这份任务单用于启动第一轮并行开发。

目标不是“每个 agent 都做一堆事”，而是让三条线各自完成一个**可验收的最小闭环**，然后由统筹 agent 合并。

## 本轮总目标

把当前已跑通的 MVP，推进到“更稳定、更能展示、更接近日常可用”的状态：

- Android 端减少音频碎片和上传抖动
- 后端把 `CaptureEvent -> DailyReview` 做得更稳定
- 媒体库与 Daily Review 体验变得更适合演示和内测

另外，本轮有一个必须统一的边界：

- 暂时**不切换**到 OpenClaw 官方 Android Companion / node 全量协议
- 当前仍然保留已经跑通的 ClawSense 配对与 ingest 数据面
- “官方控制面兼容 + ClawSense 数据面保留”的混合架构，是后续方向，不是本轮交付目标
- 媒体库主入口必须默认复用用户当前 OpenClaw 的同一地址
- 不要求用户配置域名或反向代理
- 不依赖 ClawSense 官方公网域名
- 不把 Control UI 聊天页壳子当成最终媒体库体验
- `export` 是补充能力，不是主浏览路径

## 统一规则

所有 agent 都必须遵守：

- 不要自行改共享契约，除非先提变更建议
- 每个任务都必须能被快速验证
- 每轮只交付自己负责模块的最小闭环
- 不要擅自把当前 HTTP ingest 迁移成完整 WS node 协议
- 输出格式统一为：
  1. 本轮目标
  2. 实际改动
  3. 验证结果
  4. 风险 / 未完成项
  5. 是否触碰共享契约

共享契约文件：

- `/Users/cedric/Documents/ClawSense/src/state-store.ts`
- `/Users/cedric/Documents/ClawSense/android/app/src/main/java/ai/openclaw/clawsense/data/DeviceModels.kt`

## 并行策略

本轮可以并行的部分：

- Android / Sensor Agent：可独立并行
- Backend / Event Intelligence Agent：可独立并行
- Product Surface / Review Experience Agent：可先做不依赖协议变更的部分

本轮需要后合并的部分：

- 如果 Backend Agent 改 `/api/clawsense/library`、`/api/clawsense/reviews` 的 JSON 结构
- Product Agent 必须在合并前重新对齐媒体库与 Skill 文案

建议合并顺序：

1. Backend / Event Intelligence Agent
2. Android / Sensor Agent
3. Product Surface / Review Experience Agent
4. 统筹 agent 做最终集成和验收

## Agent 1: Android / Sensor Agent

参考 prompt：

- `/Users/cedric/Documents/ClawSense/docs/agents/android-sensor-agent-prompt.md`

建议分支名：

- `codex/android-sensor-round1`

### 本轮目标

把 Android 采集端从“能跑”推进到“更可控”：

- 减少无意义音频碎片
- 让上传失败后有最小重试能力
- 保持服务状态反馈准确
- 不破坏当前已验证的图片上传链路

### 本轮任务

#### Task A1: 音频片段节流与去碎片

目标：

- 显著减少当前大量 `rms=0.00x` 的短碎片音频上传

建议方向：

- 增加最小语音长度约束
- 增加上传冷却时间
- 或在客户端先做更保守的连续语音归并

优先文件：

- `/Users/cedric/Documents/ClawSense/android/app/src/main/java/ai/openclaw/clawsense/sensors/AndroidAudioSensorHal.kt`
- `/Users/cedric/Documents/ClawSense/android/app/src/main/java/ai/openclaw/clawsense/service/SensorForegroundService.kt`

验收标准：

- 连续 1 分钟佩戴测试后，音频事件数明显下降
- 仍能稳定触发真实说话片段上传
- 不影响心跳和图片上传

#### Task A2: 上传失败最小重试

目标：

- 当音频或图片上传临时失败时，不要直接丢失

建议范围：

- 只做最小内存级或轻量本地队列
- 不做复杂断点续传

优先文件：

- `/Users/cedric/Documents/ClawSense/android/app/src/main/java/ai/openclaw/clawsense/data/DeviceSessionRepository.kt`
- `/Users/cedric/Documents/ClawSense/android/app/src/main/java/ai/openclaw/clawsense/service/SensorForegroundService.kt`

验收标准：

- 模拟一次网络中断后，恢复网络能重试最近失败的上传
- 不引入明显卡顿或崩溃

#### Task A3: 服务状态与最近活动提示

目标：

- 让用户不仅看到“运行中”，还知道最近发生了什么

建议范围：

- 在 UI 状态卡中增加：
  - 最近一次音频上传时间
  - 最近一次图片上传时间
  - 最近一次错误提示

优先文件：

- `/Users/cedric/Documents/ClawSense/android/app/src/main/java/ai/openclaw/clawsense/MainActivity.kt`
- `/Users/cedric/Documents/ClawSense/android/app/src/main/java/ai/openclaw/clawsense/MainViewModel.kt`
- `/Users/cedric/Documents/ClawSense/android/app/src/main/java/ai/openclaw/clawsense/data/DeviceSessionRepository.kt`

验收标准：

- 启动服务后，用户能看见最近上传活动
- 停止服务后，状态仍明确回到 `已停止`

### 本轮不做

- 视频采集
- 语音控制开启视频
- 大规模 UI 重做
- 多机型全兼容
- 官方 Android Companion / node 协议全量迁移

## Agent 2: Backend / Event Intelligence Agent

参考 prompt：

- `/Users/cedric/Documents/ClawSense/docs/agents/backend-intelligence-agent-prompt.md`

建议分支名：

- `codex/backend-intelligence-round1`

### 本轮目标

把后端数据层从“能存”推进到“能稳定生成可读回顾”：

- 事件窗口更稳
- DailyReview 更稳
- fallback 更清晰
- retention 更完整

### 本轮任务

#### Task B1: 事件窗口与会话归并稳定化

目标：

- 让 `CaptureEvent` 更接近日常会话，而不是单纯素材列表

建议范围：

- 优化 `windowId` 归并规则
- 对音频窗口、活跃图片窗口、基线图片窗口的规则写清楚
- 补 2 到 3 个针对窗口归并的测试

优先文件：

- `/Users/cedric/Documents/ClawSense/src/state-store.ts`
- `/Users/cedric/Documents/ClawSense/test/state-store.test.ts`

验收标准：

- 同一段连续对话不会被拆成过多独立窗口
- 图片能稳定挂靠到活跃窗口或基线窗口
- 测试能覆盖关键窗口规则

#### Task B2: DailyReview 质量与缓存策略

目标：

- 让 `openclaw clawsense review today` 输出稳定、结构固定、重复调用可控

建议范围：

- 稳定 `DailyReview.sections`
- 处理空数据日
- 明确 `force=1` 和缓存命中行为
- 保持 multimodal preferred + heuristic fallback

优先文件：

- `/Users/cedric/Documents/ClawSense/src/review-engine.ts`
- `/Users/cedric/Documents/ClawSense/index.ts`

验收标准：

- 同一天有事件时，review 能稳定生成
- 同一天无事件时，行为合理而不是报错
- `force=1` 能重算，默认可复用缓存

#### Task B3: retention 与媒体根目录整理

目标：

- 让原始素材管理真正可维护

建议范围：

- 补充 retention 行为测试或 smoke check
- 检查 `mediaRoot`、`artifactRetentionDays`、`storageRelPath`
- 确保删除原件后不会把事件索引搞坏

优先文件：

- `/Users/cedric/Documents/ClawSense/src/memory-store.ts`
- `/Users/cedric/Documents/ClawSense/src/config.ts`
- `/Users/cedric/Documents/ClawSense/src/state-store.ts`

验收标准：

- 超期 artifact 会被标记并删除原件
- 事件和 DailyReview 不因原件删除而损坏

### 本轮不做

- 引入新 STT provider 作为主路径
- 视频事件模型
- 大规模 API 重构
- 把当前 ingest 路径整体替换成官方 Android Companion / node 协议

## 统筹 Agent 本轮任务

统筹 agent 本轮要做的事：

1. 审查 Backend Agent 是否改动共享契约
2. 审查 Android Agent 是否引入新的上传字段或行为变化
3. 审查 Product Agent 是否假设了尚不存在的 API
4. 审查媒体库方案是否仍然把 Control UI 或 ClawSense 官方域名当成默认入口
5. 合并顺序控制：
  - 先 backend
  - 再 android
  - 再 review experience
6. 做最终 build / test / 文档一致性验收

## 本轮结束后的验收问题

这一轮结束后，统筹 agent 应该能回答：

1. Android 是否减少了碎片音频？
2. `DailyReview` 是否更稳定？
3. 媒体库是否更接近可展示？
4. 文档是否已经能支撑外部合作者理解系统？
5. 有没有共享契约变更需要同步所有 agent？
