**Android优先，复用当前客户端；受控分享、联系人、OCR与统一随身缓存在P2交付，桌面输入按J推进，手机独立权威及受控屏幕来源按M/L推进。主手机基础体验不等待手表。**

G2 Host共同身份、快照、权限、审核和删除主体已有实现与限定回归；Android新缓存/墓碑协议待真机补验。分享、本地OCR、联系人及收件仍是未完成联合验收的初稿。实际范围见[G2记录](validation/g2-unified-2026-10-14.md)和[G0/G1基线](validation/g0-g1-closeout-2026-10-14.md)。

## 数字之眼与现场助手的关系

现场声音、画面和用户选定的数字材料进入同一人物、项目、面谈及工作体系。手机数字入口可以在相机/麦克风未开启时使用，分享与采集有独立授权。用户先决定片段和处理范围，再让所选Agent使用这些证据；截图只能支持实际展示的内容。

| 节点 | 职责 | 交付归属 |
| --- | --- | --- |
| 旧手机或兼容相机 | 保存知情的现场声音、画面、短片及时间，接受显式现场交互 | 总计划A/D/E；兼容相机先验证文件/媒体导入 |
| Android主手机 | 分享收件、联系人确认、OCR/裁剪、背景/成果缓存、随身问答和任务入口 | I/N，独立权威接M |
| 桌面伴随服务 | 当前权威服务、分析/检索、Agent连接器、工作台和数字材料入口 | G2/H/J/K；以后可作增强节点 |
| 共享证据记忆 | 来源、身份关系、约定、更正、输入版本、权限和成果选择 | 复用G2语义，新增来源扩充授权与验证器 |
| 执行引擎 | 使用获准上下文完成真实工作，持久化进度、取消及产物 | H；默认DSH、第二宿主Codex，其余接K |

一台Android可分别测试采集角色和主手机角色。两种连接独立保存；数据归属按workspace选择。并发双设备、两个独立连接的撤销及同步仍需实际双设备验收。当前各验证库独立，不通过合并JSON冒充已经成为同一空间。

## 输入方式与边界

| 来源 | 首选方式 | 记录的覆盖 | 批次 |
| --- | --- | --- | --- |
| 微信/WhatsApp等聊天片段 | 用户分享截图、选择图片、粘贴选定文本 | 可见片段/选定文本，不推定全部历史、对方已读或发送回执 | I |
| 联系人与名片 | 系统选定联系人/字段、名片图或文件 | 用户选择的资料；聊天身份与现场说话人另行确认 | I |
| 手机文件 | 用户选择文件，提取获准片段，原件另授读取 | 指定文件/页/片段及解析缺口 | I/J导入契约 |
| 桌面网页/选区 | 浏览器主动分享当前页或选择内容 | 已获准页面内容、URL、获取时间，保留可见/选定范围 | J |
| 桌面文件/文本/截图 | 工作台导入用户选定材料 | 指定材料及引用范围 | J |
| Mac指定窗口 | 原型先验证系统能力，正式采集限定窗口与时长 | 实际捕获画面、缺口和停止范围 | J原型/L交付 |
| 手机屏幕 | 用户单独启动并限定的屏幕采集 | 当次捕获，受保护/不可获取内容保持缺失 | L |
| 指定应用通知 | 用户选择的通知入口 | 实际收到预览，不推定完整会话或历史 | L独立评估 |
| Agent成果 | H真实产物回写，保留工作、来源和审核状态 | 草稿/文件及执行回执；送达需要对应依据 | H/I/N |
| 获准身体活动信息 | 独立来源接口与授权 | 实际记录和精度，不据此确认身份或情绪 | G/M后按P试点 |

网页、文件、窗口等新来源需扩充能力声明、source类型、权限规则和解析检查；不能借用旧来源类型绕过授权。数字文字和截图中的命令仍是观察材料，不能自己触发工具执行。

平台接口、来源grant、临时URI、屏幕授权和分发条件在实施对应批次时核验。主路径使用用户主动交付材料；通用应用历史读取和GUI自主操作按实际接口单独扩展。

## Android收件与本地处理

I的任务覆盖以下完整顺序：

1. 接收单项/多项系统分享，提供图片/文件选择及粘贴入口；检查类型、大小和授权URI。
2. 用稳定事件标识保存已接收素材到App私有收件，临时URI失效后仍能恢复；重放分享和上传重试去重。
3. 预览、裁剪或选定文字；可用的本地OCR保留文字区域、原图位置和不确定项，敏感区域处理后再交付。
4. 选择人物/项目/面谈与可交付范围；同名只提示候选，聊天账号关联另行由本人确认。
5. 按用户选择同步原件或派生片段；失败保持清楚的本地/待同步/失败状态，不假报入库。
6. 接收统一背景、事实/承诺、工作状态和审核成果缓存；手机问答及任务使用H共同入口。
7. 支持取消上传、离线编辑、撤销和删除同步，保存版本冲突供用户复核。

OCR测试包含中英文、长图、遮挡、暗色主题和多图；校对OCR只确认文字内容，不自动确认人物、事件发生时间或最终承诺。原件与派生裁剪/脱敏片段各有引用关系。

传感器短时补传、本地数字收件和长期记忆缓存分别设字节、事件及保留策略。现有6条传感器补传上限不作为长期记忆容量。容量内恢复有明确结果，超限拒绝或丢弃需显示缺口；本地处理失败允许用户保留原图或手动文字，处理位置仍明确。

## 身份与来源契约

复用G2的持久workspace、来源别名和可撤回身份关系。现场speaker、系统联系人、聊天昵称与账号标识先保持独立；本人确认才建立关联。同名、群聊、公司热线、多账号及共享联系人进入反例。

新增数字事件的目标契约包括：

| 字段组 | 必须表达的内容 |
| --- | --- |
| 标识 | 事件、workspace、来源、设备、schema版本和客户端幂等标识 |
| 来源 | 来源类型、声明等级、选择方式及已验证grant；用户填写的应用名保留为声明 |
| 时间 | 采集/分享时间、Host接收时间、实际事件时间、时区/精度及依据 |
| 内容 | 原件、文字/区域、OCR分析版本、父事件和裁剪/脱敏关系 |
| 覆盖 | 可见片段、选区、文件页或连接器范围，完整性和已知缺口 |
| 关联 | 人物、互动、项目及确认状态，关系版本和依据 |
| 处理 | 内容校验、质量、处理位置及实际受控接收方 |
| 授权 | 可读取/交付的操作与主体、保留、撤销和删除状态 |

旧字段按其原义适配，未知项保持未知。今天分享上周聊天时，receivedAt不会改成聊天发生时间。“周四”保留原词，缺日期基准时不填具体月日。片段里的发出气泡只能证明看见该内容，不能自动写成平台已发送/送达。

原件、机器分析、用户解释与成果审核分别保留版本；相互矛盾的来源并存，由确认决定当前约定。后续变化使依赖工作过期，删除或撤销后则不可用。Agent记录的确认保留其写入来源，不由正文“用户已确认”提升权威。

## 随身记忆与手机任务runtime

I/N先交付获准背景与成果的随身缓存：人物背景、确认事实、未完承诺、当前已接受成果、证据引用、新鲜度，以及持久化提问和任务状态。电脑离线时仍能查看这些缓存，新增任务显示排队或中断。手机独立处理当前新问题的范围由F实际能力决定。

缓存包含来源版本与授权检查时间。在线读取/播报前复核；后台同步发现来源不可用时清除受管理内容并停止旧输出。离线时立即撤销所有副本不作为承诺；缓存有效期限和授权新鲜度必须可解释。

H保存请求与真实宿主运行的关联，使用幂等重试、进度、取消及中断恢复。任务不因网络断开显示完成，模型声称取消也不能替代执行端结果。正文/文件回到手机，并保留保存、本人审核、取代、发送及送达的不同状态。

手机的“确认人物/事实/成果”需可信本人操作来源和相应权限，复用G2确认权威规则；分享记录、图片文字和Agent回答不能自行批准外部动作。有限任务工具和预算按用户所选范围开放。

## 桌面数字入口

J先扩展既有工作台的文件、文字和截图导入，展示来源、项目、范围、解析缺口及处理位置。浏览器入口由用户主动分享当前页或选区，优先结构化内容和URL；附件/截图作为补充证据。

Mac指定窗口先做原型，进入正式限时采集后使用L共同的授权、状态、停止与资源规则。其它系统各自验收。当前桌面伴随服务和工作台已有，桌面数字输入仍需实现；原生桌面App按用户需求另行扩展，不把新App作为基础输入前提。

桌面材料与现场/手机材料使用同一身份及权限检查。可查看某个文件不自动扩大到其它窗口、网页标签或本机目录。

## 手机权威与同步

M通过手机存储适配及同步协议推进独立记忆；G2的目录迁移工具提供现有Host检查点规则，不直接证明手机权威或双端同步已实现。

- 各端独立保管本地资料与待同步事件；以稳定事件标识和内容校验去重。
- 离线更正携带预期版本；冲突保留供复核，不静默覆盖另一端确认。
- 删除墓碑覆盖原件、分析、身份关联和派生缓存；旧队列与晚到任务不复活。
- 权威转移先停写/形成一致检查点，核对版本与范围，再显式切换所有者；新事件和删除通过前滚恢复保留。
- 当前同一workspace只有一个权威写入端。端间通过协议协同，不让两个程序共写目录。
- 双设备反例包含连接串用、错误项目、重新配对、撤销、重复、时钟/发生时间差异和断网。

纯手机本地、自有设备协同和外部模型各自声明并测量。Host的SenseVoice不是Android端识别实现，手机TTS也不能单独证明全链离线。获准交给外部Agent的内容及其副本保留边界按总体计划说明。

## 批次映射与验收

| 旧细案 | 现行批次与阶段 | 联合结束条件 |
| --- | --- | --- |
| D0共同基础 | G2现有主体，I/J/M消费 | 两类证据、人物和成果采用同一版本与授权规则，旧接口保持 |
| G3共同执行入口 | H，P2；D负责Live轮次 | 手机请求触发真实DSH工作并回流，第二宿主复用，取消/恢复可检查 |
| D1主手机 | I/N，P2；缓存/权威升级接M | 现场—联系人—线上变化—两Agent—手机成果—下次复用通过，不等待手表 |
| D2桌面输入 | J，P2基础/P3扩展 | 选定文件/网页关联同一项目，权限不扩散；窗口正式采集接L |
| D3屏幕/通知 | L，P3 | 独立授权和停止、覆盖、资源、恢复及删除分别通过 |
| D4手机任务增强 | F/H/M及P，P2至P5 | 声明端侧能力可复核，任务状态恢复/取消，公开与私密输出分开 |

共同故事按总体计划执行：先保存现场周五约定，再分享周四片段，确认人物和当前约定，DSH形成真实草稿，另一宿主读取最新版本；本人接受正确稿，手机在电脑离线时可查缓存，下次交流继续。另测旧稿拒绝/取代、晚上传、同名误关联、撤销和离线删除补传。

自动检查先覆盖导入、去重、权限、版本、状态和恢复；真机集中检查分享/选择器、OCR、断连、缓存、停止与联合体验。分享数量和录屏时长是运行数据，用户回查、纠错耗时和下次复用才决定继续投资哪个来源。
