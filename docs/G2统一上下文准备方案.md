## 目标与边界

G2 要让现场录音、画面、用户选定的聊天片段、联系人以及 Agent 成果，能够围绕同一个人和项目形成有依据、可纠正、受权限约束的记忆。G2 先建立共同规则；手机自动调用 Agent 属于 G3，主手机实际分享与联合体验属于 G4。

准备工作可以在 G0/G1 剩余验收期间开展，包括源码差距盘点、契约草案、迁移方案、合成数据和离线检查。正式改变旧接口、资料库或权限默认值前，仍需完成[主计划](./跨Agent早期插件开发计划.md)的前置基线。不能以准备完成宣称 G2 交付，也不扩大主手机功能。

本轮交付：[契约类型草案](./contracts/g2-context-v1.d.ts)、[只读迁移盘点工具](../scripts/g2/migration-inventory.mjs)及[合成检查](../scripts/g2/migration-inventory.test.mjs)。它们未被 `index.ts`、伴随服务或 Android 引用。

## 一、共同标识与人物关系

每个资料空间拥有持久、独立的 `workspaceId`，不能用当前路径、LAN 地址、设备 ID 或默认 `memoryNamespace=clawsense` 代替。复制备份保留同一空间身份；导入到另一个空间是显式操作，不能自动拼接两份目录。

共同标识采用 `workspaceId + objectKind + objectId`。personId 是稳定标识，姓名只是可修改的标签。旧物理 personRef、面谈 personId、数字 personId 的别名按来源分别保存；即使字符串相同也不能直接跨库合并。只有用户确认关系后才能共用人物。

| 关系 | 规则 |
| --- | --- |
| 同名两人 | 分开创建；同名仅生成候选，不自动合并 |
| 旧面谈与数字联系人 | 用户明确确认关联；记录决定者、时间、版本与依据 |
| 联系人与微信身份 | 联系资料不能证明微信身份；platform/account/externalId 分别确认 |
| 说话人 | `SPEAKER_00` 仅在具体设备、录音事件和区间内有效；不得跨录音当成同一个人 |
| 误关联 | 撤回旧关系后建立新关系，保留历史；相关快照和成果过期 |
| 人物合并/拆分 | 第一批先提供可撤回的关系，不做不可逆实体合并；之后再支持受控合并与拆分 |

旧 speakerRef 若缺 event/window/device，保留为待复核标签，不能因姓名相同补上人物。多次面谈曾因工作台同名复用一个 ID 时，应提示歧义，不能在迁移时替用户选择归属。

## 二、来源、时间与可信程度

原件、机器识别、人工解释分别存储，不用人工更正覆盖原音频或图片。`Evidence` 引用 `Artifact` 与 `Analysis`；机器重新识别产生新分析版本。原件字节无需移动进共同 JSON，物理和数字目录可以继续隔离。

每条证据明确保留：来源类型、设备、来源声明等级、覆盖范围、采集/分享时间、接收时间、实际事件时间及其依据。

- `capturedAt` 是录制或分享时间；`receivedAt` 是 Host 接收时间。晚上传不表示晚发生。
- 聊天发生时间放入单独的 `occurredAt`，携带精度、时区与依据；无法确认则保持未知，不伪造精确时间。
- 用户分享的图片只能证明可见片段；“来自微信”若由用户填写，只标为来源声明。
- OCR 文字被用户校对，表示转写内容已复核，不表示聊天身份、事件时间或承诺一定被确认。
- 老物理事件缺可靠 receivedAt 时，保留 legacy createdAt 的来源含义与未知项，不在迁移时改成当前时间。
- “周四”保留原词。缺少明确日期、时区或相对时间基准时，不自动填成具体截止时间。

## 三、事实、纠正和成果确认

共同断言至少区分：行动方、动作、接收方、数值/内容、期限原词及证据引用。录音“周五”与线上片段“改周四”并存，形成候选变化；用户确认当前约定后，保存明确的取代关系。不能用最新导入时间自动覆盖旧约定。

状态为 proposed / confirmed / contested / withdrawn。纠正是追加记录，需当前 expectedRevision，并记录 supersedes；新的相反依据出现时显示冲突，不悄悄覆盖已确认结论。

确认权威分开：模型推测、Agent 代为记录用户确认、本人确认。认证证明“谁写入”，不能单独证明“用户确实说过”。旧 Agent 纠正按原历史保留，并显示记录来源；不迁移为凭空新增的本人确认。未来宿主提供可信用户指令回执时，才提升相应确认依据。

本轮 G1 已暴露期限与接收方写错的情况，成果契约必须补齐：

- `saved` 与 `reviewed/accepted` 分开。完成工单表示真实成果已保存，不表示内容正确。
- 保存不可变的 resultId；拒绝旧稿与接受新稿有版本和决定者。
- `supersedesResultId` 明确新稿替代哪份旧稿；下次 briefing 优先返回当前被接受、仍获授权且来源未过期的成果。
- 未确认稿可以明确请求读取，但不能默认当作已确认约定；旧 completed 成果迁移为“已保存、未复核”。
- 草稿、已发送、已送达分别记录；没有发送回执时，不显示已发送。

## 四、共同上下文快照与过期判断

每次工作创建或执行使用不可变 `ContextSnapshot`，保存实际消费对象的引用与版本：面谈、证据、原件可用状态、ASR/OCR/视觉分析、人物/身份关系、纠正与其它输入成果。仅保存 dependency 引用与摘要校验，不将未授权全文再复制一份。

共同读取采用权威服务内的 contextSequence：读取前后检查相关版本或读事务；发生变化则重读。异步分析回填必须先提交相应版本/序列，再使新读取可见。当前三个 JSON 各自原子写入不等于已经有跨库原子快照，正式实现需写入协调器和可恢复日志。

| 变化 | 工作读取结果 |
| --- | --- |
| 本次依赖未变 | current |
| 相关识别、人物归属、约定或面谈范围变化 | stale，保留旧成果与来源；重新生成由新工作/新成果承担 |
| 无关人物/无关事件变化 | 不使本次工作过期 |
| 当前授权被撤销 | unavailable；不返回正文、标题摘要或依赖详情 |
| 依赖被完整删除 | unavailable，进入派生清除流程；不能只标 stale 后继续暴露正文 |
| 原件自然到期、转写获准保留 | 说明原件不可回听/回看，按 retained-analysis 策略读取；不能伪称仍能复核原件 |

权限在每次读取时重新检查，不因为保存快照时有权就永久有权。policyEpoch/deletionEpoch 是检查标记，不能让所有不相关改动都自动触发 stale。

## 五、共同权限、保留和删除

认证主体由 Host/传输层提供。角色区分本人、Agent、设备；摄像采集、数字分享、上下文读取、人工确认和对外发送不是同一项权限。

共同范围包括 workspace、项目、可选面谈、来源类型，以及 read-metadata / read-analysis / read-raw / read-result。原件权限独立；有转写权限不能顺便下载音频。未归项目的旧物理素材，在严格模式下默认仅本人可读，不能迁移成所有项目共享。

所有消费入口都走同一个判定：MCP/stdio、HTTP、原图/音频、面谈/briefing、检索、人物列表、成果导出、工作台、原 OpenClaw 入口及未来缓存同步。筛选后再计算列表/统计，避免泄漏未授权标题、联系人、关联项目或数量。包含多来源内容的结果要求全部依赖获准；不尝试直接从自由文本里删几句话来代替权限隔离。

旧凭据的物理整库读取与新增数字范围分别盘点，不在迁移时把物理授权扩大到数字内容，也不在准备阶段改变既有读写。严格范围切换前显式复核旧授权映射；新增无项目素材采用本人范围，不能用未知项目自动填成通配符。

删除区分两种意图：

1. **只删除原件/原件到期**：原件不可读；获准保留的识别和记忆仍可存在，并显示不可回查原件。
2. **删除证据及其派生内容**：先写墓碑并立即阻止读取，再清除受管理原件、识别、journal、索引、摘要、纠正引用正文、成果副本与可管理缓存。保留不含正文的审计和去重键。

完整删除是可恢复的传播任务：pending → managed-copies-purged；清除失败时继续阻止读取，重启重试，不能先报告完全擦除。原离线队列重试同一事件仍应被墓碑拒绝；设备与事件的去重键迁移后继续保留。撤销后晚到的处理任务与补传不能发布新可读结果。

外部 Agent 已复制到自己的对话或文件的内容无法承诺全部擦除；回执明确区分可管理副本与外部未知副本。第一批默认保留墓碑，不能为了减少文件大小清除防复活记录。

## 迁移与回滚方案

1. 在 G0/G1 基线稳定后，由一个权威服务协调停止写入或生成一致检查点，保存权限受限的备份与各文件哈希。不能边复制边声称快照一致。
2. 对离线副本运行结构盘点，识别同名/旧ID歧义、说话人缺范围、未归项目、分析缺版本、未复核成果及删除依赖。
3. 创建持久 workspace 标识和按来源分开的别名表，保留旧 ID；不自动合并同名或跨库同字串 ID。
4. 初始分析版本以已存内容的校验记录建立；缺失原件与删除原因未知单独记录，不重建不存在的音视频，不猜历史变化次数。
5. 在新位置建立共同目录、依赖图、快照与迁移日志；legacy 文件不就地改写。新结构仅作为一个权威写入端控制的旁路索引，不能有第二个进程独立写它。
6. 在合成副本先验证新旧读取一致与差异清单；再做受控数据副本影子读取。任何权限差异、未决身份或删除传播问题均不能静默通过。
7. 切换统一读取和写入协调器时停旧写入，维护全部已支持 ingest/MCP/OpenClaw 入口。所有源文件哈希/迁移版本仍匹配才应用，防止盘点之后数据又变了。
8. 若仅生成影子结构，可丢弃影子回到旧文件；若已接受新写入，必须使用迁移日志完成前滚或兼容回放。不能直接恢复旧备份而丢掉新增事件；已删除/撤销的墓碑不得因回滚被复活。

只读工具目前只完成第 2 步的结构盘点，不是完整 schema 校验或自动迁移计划。它没有 apply 模式，不读取模型，不启动服务。输入需是副本，存在写入锁或软链接时拒绝；不能仅凭“没找到锁”断言旧 OpenClaw 没有运行，副本一致性仍需上一步的检查点保证。

## 分批实现与结束条件

| 批次 | 实际实现工作 | 完成证据 |

| G2-A：标识与人物 | Workspace 元数据、别名表、人物登记、作用域内 speaker link；移除工作台同名自动复用；保留旧接口适配 | 同名独立；跨来源显式确认/撤回；旧注释不丢失；旧配对与 ingest 回归 |

| G2-C：快照与成果 | 写入协调器、共同依赖版本、成果接受/拒绝/取代、统一 briefing | ASR回填和身份纠正使相关成果过期；无关变化不误报；旧错误稿不默认复用 |
| G2-D：权限与删除 | 全入口范围检查、原件独立许可、完整删除任务、墓碑与恢复 | 所有入口不泄露；删除/撤销立即阻止读取；受管理副本清除；离线重试不复活 |

A 到 D 的代码可先在隔离模块与合成副本开发，接入当前数据面依赖前置验收。跨库一致性与权限是所有消费路径的共同前提，不能将完成 A 就标成 G2 完成。
