# G2 统一上下文实现与使用

日期：2026-10-14。方向依据[VISION.md](../VISION.md)，本批承接[现行执行计划](./产品演进路线与执行计划.md)中的共同记忆与权限工作，以及[G2准备方案](./G2统一上下文准备方案.md)。Live、自动宿主执行、主手机联合体验和公开分发继续按各自门槛推进。

## 本批实现

| 批次 | 实现 | 使用入口 |
| --- | --- | --- |
| A 身份与来源 | 持久workspaceId，按physical/workflow/digital区分旧人物别名，同名不合并，可撤回的人物/账户关系，按事件、设备及区间绑定说话人 | workspace、people、person_create、person_link、speaker_link、legacy_annotations |
| B 证据与纠正 | 原件留原存储；物理分析版本另存，旧转写可查；发生/采集/接收时间分开；确认权威与断言状态分开，动作、接收方和期限原词分别保存 | analysis_history、memory_correct、session_evidence；真人owner确认可优先于旧转写用于事实问答 |
| C 工作与结果 | 共同版本快照，相关输入变化使工作过期；结果保存与审核独立，可接受/拒绝、明确替代旧稿，默认复用仅选择当前可读且已接受成果 | context_snapshot/get、work_create/get、result_review、selected_results、briefing；本地工作台可审核 |
| D 权限与删除 | 项目/来源/面谈及metadata/analysis/raw/result分开；写入另授能力，MCP/HTTP一致筛选；公开范围和处理位置检查；记录模型请求接收方，墓碑先阻读、再清理并重试；手机检查快照和清理已删除补传 | context_policy、device_context_policy、context_delete、deletion_status、context_export、disclosure_receipts |
| E 迁移与恢复 | 停写后盘点、源哈希校验、独立副本、路径重定位、authority切换、当前数据前滚式回退、删除墓碑保留、死亡进程锁检查与恢复 | context-plan/migrate/activate/rollback/recover |

共同目录为`plugins/clawsense/unified/`。原`state.json`、`workflows.json`、`digital/context.json`和Android ingest入口继续存在；新增目录不允许第二个进程独立写入。source读取和提交由同一空间的协调器串行，分析、人物、成果与删除的版本进入共同目录。向旧接口增加可选字段，不承诺旧二进制能读取所有新写入字段；目录回退使用本批兼容读取器。

人物姓名只是标签，旧ID相同不证明是同一个人。旧speaker注释保留供owner复核，不直接作为跨录音身份；新speaker_link明确绑定一段音频。旧人物同ID不同标签会提示歧义，无法由迁移替用户选定。

分析版本的recordedAt表示共同目录登记时间，producedAt只有已知Host提交分析的时间才提供。旧素材缺生产时间时明确标为legacy-production-time-unknown，不把今天的导入时间冒充过去的分析完成时间。原件元数据区分available、expired、missing与deleted；自然到期的原件不再放行下载，分析是否保留单独处理。

## 个人连接与办公连接

旧凭据的物理整库权限保留，不自动扩大到数字来源。未指定共同范围的旧安装模式标为`legacy-physical-library`，适用于已信任的个人现场记忆连接；它不能被描述为已经隔离的办公项目授权。需要选择性授权时，生成新的限定连接，再按需要撤销旧连接。

```bash
clawsense connect codex --context-project expo \
  --context-source audio --context-source image --context-source shared_text \
  --context-operation read-metadata --context-operation read-analysis \
  --context-operation read-result --context-capability create-work \
  --context-processing selected-external --out /私有目录/codex-expo
```

没有read-raw不能顺便下载录音或原图，没有写入能力不能更正或完成工单。各Agent用自己的可撤销凭据。操作身份来自传输，工具参数中的actor不能提升权限。

旧未归项目的现场来源不会因机器推断projectRefs而获得严格模式授权。Owner可先用context_list查看引用，再用context_policy明确归项目；device_context_policy只设置未来采集的默认范围，已有证据不回溯改归属。物理、数字人物关联不会自动赋予其它项目或来源读取权。

原OpenClaw主入口也可在插件配置中设置`primaryAgentContextScopes`、`primaryAgentContextCapabilities`和`primaryAgentProcessingLocation`。不设置范围保留旧可信主宿主适配；明确空范围意味着不授权。source接收方、私密/公开及模型处理位置仍另外检查。

处理位置是owner声明的授权边界。自带密钥、使用兼容SDK或将客户端装在本机，不独立证明模型本地。默认外部Agent被按selected-external处理；local-only来源阻止网络推理回退。模型调用记录URL origin及授权引用，不记录凭据；收到HTTP响应不代表推理正确，失败也不能认定供应商没有收到输入。

## 纠正、审核和下次复用

`memory_correct`保留原件及历史。Agent代为记录默认proposed，独立owner动作可confirmed；新的proposal不会静默覆盖同对象已有owner确认。相对期限保留`deadlineLiteral`，没有单独确认的日历基准不由服务自动推算日期。`action`及`recipientPersonId`可以准确表达“客户收到方案”，不能用同一天发送代替同一天收到。

completed表示成果已经保存。旧completed成果进入pending审核，不由迁移自动接受；result_review只有本地owner身份可调用。接受、拒绝或替代都有独立版本。工作台的“接受此稿”不会发送消息，“替代旧稿”由用户明确选定。当前来源已更新的稿不能被接受为当前成果，仍保留历史。

旧稿缺创建时共同快照，owner接受时绑定当前复核快照；之后分析或关联变化不继续默认复用。该快照证明审核时的输入范围，不反推旧Agent当时实际读取了这些资料，也不保证模型语义正确。

共同快照保存对象及版本，不因为无关人物变化使全部工作过期。保存时有权不代表以后一直有权；每次读取重新检查。外部Agent在ClawSense之外使用的上下文不是此快照的可验证范围。

## 删除与客户端缓存

raw-only删除原件并保留已获准的分析；evidence-and-derived先写墓碑、拒绝读取和相同采集重试，再清理受管理原件、分析正文、journal、摘要、工单结果、登记的查询音频/草稿及索引。索引或文件清理失败时，回执保持pending；重启或恢复命令继续处理，期间仍不返回正文。

完整删除会清空当前workspace可重建的向量检索缓存，包括Lance旧版本与片段，后续检索可退回保留的事件/journal。仅做数据库逻辑删除不足以证明旧缓存文件清除。显式配置到其它目录的索引不自动整库擦除，任务保持pending，需将其隔离导入或提供相应清理；旧隐式共享OpenClaw索引不属于本批默认缓存。

手机对新服务返回的contextSnapshotId在呈现回答前再验证，心跳复核已显示回答；来源unavailable时清除当前缓存并停止旧播放。来源删除的410回执清理对应补传副本，不把它写成上传成功。旧服务没有快照字段时保留原协议行为。

离线客户端、已经收到内容的外部Agent对话/文件，以及未登记的用户备份不属于立即可擦除的服务器副本。回执必须分别说明服务端清理、客户端后续同步和外部副本未知，不宣称对方所有副本已经删除。源级授权不自动从自由文本中识别并删去私人句子；混合内容分享前需要用户选择范围。

## 迁移操作

停服务并核对锁释放后：

```bash
clawsense context-plan --state-dir /原资料库 --out /私有目录/g2-plan.json
clawsense context-migrate --state-dir /原资料库 --plan /私有目录/g2-plan.json --target-dir /新的独立资料库
clawsense context-activate --state-dir /原资料库 --plan /私有目录/g2-plan.json --target-dir /新的独立资料库
```

plan只含结构计数和哈希，不含录音、正文、账户或凭据。副本准备不改原文件；盘点之后源哈希改变就拒绝旧计划。激活将原目录标记为authority已移动，更新版不会在旧目录重新启动第二个写入端。手机/宿主连接选择当前authority服务，不能两个写入者共用同一目录。

哈希检查同时覆盖受管理原件、草稿、查询副本和索引文件，文件名用不透明键表示；只改原件字节而没有改JSON也会使旧计划失效。离线恢复没有可用索引清理器时，存在索引的删除任务保持pending，待正式运行时重试，不冒充已清除。

回退采用当前数据前滚回放，不恢复旧备份丢掉新事件：

```bash
clawsense context-rollback --state-dir /原资料库 --target-dir /当前独立资料库
clawsense context-recover --state-dir /需恢复的资料库
```

恢复先确认记录的进程已死亡，不偷取仍活跃的锁。回退携带当前事件、工作及删除墓碑；不是任意降级旧二进制。跨目录的自定义mediaRoot需要显式导入映射，当前命令对此拒绝自动猜选。用户自行复制到其它位置的快照/外部共享索引不能被这里的回执冒充已擦除。
