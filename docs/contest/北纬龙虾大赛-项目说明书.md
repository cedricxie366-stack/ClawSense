## 第 1 页：封面

标题：

`ClawSense：把旧 Android 手机变成 OpenClaw 的全天候感知节点`

副标题：

`让 AI Agent 从“只会对话”进化为“能感知、会回顾、可追问”的生产力伙伴`

建议署名：

- 参赛赛道：`生产力龙虾`
- 项目类型：OpenClaw 插件 + Android 客户端
- 项目阶段：`已完成可运行 MVP，主链路已验证`

封面一句话：

`ClawSense 复用旧手机的麦克风与摄像头，把日常环境中的关键音频和图像变成可索引、可回看、可生成 Daily Review 的连续上下文。`

## 第 2 页：问题定义

标题：

`为什么今天的 AI Agent 还缺一双“眼睛”和“耳朵”？`

正文：

- 当前大多数 AI Agent 仍然停留在“你问一句，它答一句”的模式，缺乏连续感知能力。
- 在真实工作流中，很多重要信息并不会进入聊天框，而是散落在会议、口头交流、临时讨论和环境变化里。
- 人们每天都会丢失大量上下文：今天和谁聊过、某件事何时发生、哪个细节值得追问、明天应该继续关注什么。
- 与此同时，大量旧 Android 手机被闲置，明明具备摄像头、麦克风和网络能力，却没有被重新利用。

结论句：

`我们想解决的不是“再做一个聊天机器人”，而是让 AI Agent 获得低成本、持续、可控的现实世界输入。`

## 第 3 页：解决方案

标题：

`ClawSense：低成本持续感知 + 多模态回顾`

正文：

ClawSense 由两部分组成：

- `Android 客户端`
  负责把旧手机变成持续感知节点，完成扫码配对、前台服务采集、音频上传、图片上传和心跳上报。
- `OpenClaw 插件`
  负责接收感知数据、形成事件窗口、提供媒体库浏览入口，并生成 Daily Review。

核心能力：

- 一次配对，长期使用
- 音频 VAD 触发采集
- 周期性图片快照采集
- 事件归并与索引
- 同主机、同源的媒体库浏览
- 面向助手式使用的 Daily Review 与 context 能力

一句话总结：

`Android 负责“采”，OpenClaw 负责“看、想、总结”。`

## 第 4 页：系统架构

标题：

`系统架构与数据流`

正文：

1. 用户用旧 Android 手机扫码配对，获得长期 `deviceSecret`
2. 手机前台服务持续运行，采集音频、图像与心跳
3. 服务端接收原始素材，并按日期、设备写入媒体目录
4. 后端把原始素材归并为 `CaptureEvent` 与事件窗口
5. OpenClaw 当前主多模态模型只分析关键窗口，降低上下文成本
6. 系统输出两类结果：
   - 原始感知浏览面：`/plugins/clawsense/library`
   - 助手式总结：`openclaw clawsense review today`

架构亮点：

- 不要求用户自建额外公网域名
- 媒体库复用当前 OpenClaw 的同一地址
- 保留 ClawSense 已跑通的数据面，未来可兼容官方控制面

## 第 6 页：典型使用场景

标题：

`谁会需要 ClawSense`

正文：

场景一：个人知识工作者

- 白天有大量临时沟通和碎片信息
- 晚上需要快速回顾“今天最值得记住的事”
- 希望把会议、讨论和环境变化整理成待办与追问

场景二：小团队 / 独立开发者

- 缺乏专门的记录与复盘流程
- 希望用低成本方式把关键现场信息沉淀为团队记忆
- 需要 Agent 帮助整理人物、项目、主题与下一步关注点

场景三：旧设备再利用

- 许多旧 Android 手机仍有摄像头、麦克风和联网能力
- ClawSense 让闲置设备变成 AI Agent 的现实世界输入节点
- 同时具备低成本和可持续价值

## 第 7 页：创新点

标题：

`创新不只是“看见”，而是“低成本地持续看见”`

正文：

创新点一：旧手机复用

- 不依赖专用硬件，不增加额外传感器采购成本
- 用旧 Android 手机直接变成可部署的感知节点

创新点二：事件窗口而非素材堆积

- 不是简单存一堆音频和图片
- 而是先做事件归并，再让大模型分析关键窗口
- 降低 token 消耗，也提高总结可读性

创新点三：同 host / 同 origin 浏览体验

- 媒体库复用当前 OpenClaw 地址
- 不要求配置额外域名、代理或第三方托管
- 更符合真实部署环境

创新点四：从“原始感知”到“助理式回顾”

- 用户既能看原始素材
- 也能得到 `Today at a glance`、时间线、关键人物、关键主题和明日建议
- 这让 ClawSense 不只是采集工具，更是 Agent 的记忆基础设施

## 第 8 页：安全、伦理与责任使用

标题：

`可用之外，更要可控`

正文：

ClawSense 在产品设计上主动遵守以下原则：

- 数据安全
  只在用户授权的设备上运行，采集权限明确，服务端按设备和日期落盘，避免无边界抓取。
- 透明可控
  用户可明确知道设备是否已配对、服务是否运行、当前是否降级；系统强调“知道能做什么，也知道不该做什么”。
- 合规使用
  项目定位是个人与团队的感知记录和日回顾，不用于攻击、欺诈、隐私窃取或未授权自动化操作。
- 尊重边界
  视频能力只作为用户可控的短片段证据增强：手动触发为基线，自动触发必须默认关闭、显式开启、可解释并受队列 / 冷却 / 上限保护；当前不做全天连续录像、不可关闭的语音开启视频、微表情或内在意图自动推断。
- 知识产权保护
  项目只处理用户自己的感知数据，不鼓励大规模抓取和复制受保护内容。

可作为加分点强调：

`我们把“安全边界”作为产品能力的一部分，而不是事后补充。`

`为什么它适合现场评审`

- 应用前景
  个人知识工作、团队复盘、低成本智能陪伴与助理
- Demo 表现
  从采集到回顾的链路清晰，适合 3 分钟内讲清楚
